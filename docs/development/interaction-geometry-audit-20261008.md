## 原规则与本轮边界

以真实键盘内容框计算，不用整屏宽高代替。工具栏44dp；普通四行键区底内缩8dp。窄屏26键三排字母同格宽，第二排两侧半格，第三排Shift/删除各1.5格；用户追加的宽屏实体错位及1000dp自动默认单独记录于[物理几何](wide-qwerty-physical-geometry-20261008.md)。26/14/手写底排共用1.2、1.2、1、3.9、1、1.7权重（总10）；展开候选左栏对符号键12%，右栏对底排回车17%，不能跟第三排删除的新宽度改变。

标准26键自动默认：360dp可用宽→360×276dp，行56dp、纵缝5.5dp；934×1493dp可用区→934×404dp，字母键帽约79.8×79.75dp。历史文档的934×415已非现公式。自定义、分体及非标准布局沿用各自默认；已存手动尺寸、显式横纵缝（含0）不迁移。

尺寸上限仍由KeyboardGeometry与KeyboardAspectGeometry共同决定。固定竖屏高上限max(228, floor(configHeight×.45))；固定横屏max(160, configHeight−navInset−28−24)，当前默认navInset24。悬浮max(228, floor(hostHeight×.70)−28)，还受实际系统栏、底留白及形状保护限制。934×1493且无额外留白的固定竖屏示例最大671dp。普通键盘不任意拉成全屏；全屏手写是独立画布模式，控件保留普通尺寸。

本轮只替换自动纵缝“只跟宽、不跟高”的旧规则：原手机默认/方形键帽行高以内不变；超出的每行高度80%给键帽、20%给间距。20%采用现有MaxGapFraction预算，这是新的高度分配决定，并非声称旧实现已有。横缝和外留白不变，不恢复已废弃的上下空白或小键帽上限。共用该度量的正常手写仍五等分，全屏继续冻结普通控件度量。

## 严格几何判据

记键区顶为T、底为B、底内缩P，四行格高R=(B−T−P)/4，纵缝G。第r行（0起）键帽顶=T+rR+G/2，底=T+(r+1)R−G/2。

| 检查 | 通过条件 |
|---|---|
| 第一排底→第二排顶、第二→第三、第三→第四 | 三缝均为G，渲染取整差≤1px |
| 键区顶→第一排顶 | G/2，无额外空白 |
| 第四排底→键区底 | P+G/2，无额外空白 |
| 同排键帽上下边 | 偏差≤1px |
| 只调整高度 | 字母格宽、横缝、左右边及44dp工具栏不动；键帽和纵缝连续增长 |
| 底排/侧栏 | 上述对应键左右边偏差≤1px，禁止仅比较常量 |
| 触摸格 | 仍覆盖完整行格，新增视觉缝不产生死区 |
| 手动与极端尺寸 | 不重算已保存尺寸；拉左时右边不动、拉上时底边不动；保留6dp方键吸附及边界优先 |
| 文字/图标 | 非滚动标签不得裁切、重叠、跨键；大字号以实际可用键帽测量 |
| 长按浮窗 | 顶排及左右端完整显示，不受卡片圆角/离屏透明层裁切，不抢输入焦点，松手即按原语义提交 |
| 日语圆盘 | 同一按键五个方向位置/圆盘尺寸不变，仅选中项高亮；始终提示设置不改变手势 |

## 追加：操作菜单统一与删除提示

用户明确否定长按后遮盖整个列表的内容替身页。此前 `LongPressMenuOverlay` 在记录区重画整块背景和一份文字/图片预览，更多及删除又使用另一个覆盖组件，删除说明无条件包含相册提示；这不是数据类型判断错误，而是视图结构和文案复用错误。

本轮改为按实际条目/按钮边界定位一个内容宽度的菜单，优先查找可见记录间的空位，没有完整空位时在面板内限高滚动。底层列表保留，不复制预览，不画整页背景；透明外部点击层只关闭菜单，避免关闭时误粘贴。尺寸、density、字号或记录内容改变则关闭过期锚点，不沿用旧坐标；后台插入导致原条目移动也适用。文字、图片、混合删除分别计数，只有含图片时说明保留原始图片。

`CompactMenuStyle`/`CompactMenuRow` 共用圆角12dp、最小行高36dp、14sp文字、18dp图标，字体放大时按内容增高。七处普通下拉入口（方案、插件、手写采集、词库方案、方案词库、词库分类、市场版本）和插件字段选择器共用外观；字段保留原锚点与选择语义。语言长按滑选只共享视觉参数，保留原44–64dp行高、坐标和连续手势。编辑表单、权限、导入和卸载确认不伪装成操作菜单。

检查要求：长按前后原记录边界相等，菜单外像素不被遮罩改变；有足够空位时菜单不覆盖原记录；窄框大字所有操作可滚动到达；RTL使用绝对本地坐标；纯文字无图片说明；外部点击不触发记录或删除。新增/更新的测试尚待本轮实际运行，不能按实现完成就标为通过。

## 剪贴板列表重排与图片预算

## 悬浮贴边恢复框错位：源码确认，未交付

用户指出恢复目标框的线条与实际落点不符。原 `FloatingKeyboardContainer` 自行读取固定宽高，用 `protectKeyboardSize(... offsetX = 0)` 计算预览，动画终点横向偏移也固定归零；实际 `restoreKeyboardDisplayMode` 则读取保存的 `fixedOffsetX`。当前平板横屏保存宽1005dp、横向偏移−244dp，宿主宽1493dp时，真实固定左边为0，而旧预览左边为244dp。该错误能直接从源码证明，无须以测试框推测。

另两处相同分歧是预览高度不包含固定模式的用户底部留白，底边使用悬浮安全距离而非固定模式实际导航留白。修复应由服务层解析固定恢复目标并传给预览，不能让预览再次独立猜测布局；保存设置不改写。

旧 `FloatingKeyboardUiTest.edgePreviewExpandsThenReleaseRestoresWithoutLeavingTheDragRow` 仅断言合成内容框预览宽度与拖条消失，没有比较真实服务松手前后四边，因此不能作为真实恢复成功的证据。新增验证需在真实IME内记录 ready 状态目标框的屏幕坐标，与恢复后 `fixed-keyboard-card` 左、上、右、下逐一比较（容许至多1dp像素取整），覆盖非零左右偏移、底部留白、导航边距并确认真实按键可输入；组件测试另行记录，不替代此项。
