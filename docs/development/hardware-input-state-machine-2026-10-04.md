# 物理键盘输入状态机与本轮修复

## 边界与事件顺序

本方案以 1.6.0 为基线，按用户最新明确规则：智能联想只能数字或点击选中，空格/回车从不确认联想。事件顺序为：语言/工具快捷键 → 剪贴板导航或内部表单 → 输入 FIFO → 当前编辑会话的候选快照 → 引擎/正文。不能在 onKeyDown 读取滞后的候选列表后直接决定数字选词。候选来源、显示顺序、编号、焦点和提交目标必须一致；触屏按键原有空格设置不由物理键盘覆盖。

## 状态与按键表

| 状态 | 空格 | 回车 | 未加修饰的 1～9、0 | 方向键 / 退出 |
| --- | --- | --- | --- | --- |
| 非英语组词，有引擎候选（含九键部分选词、日语转换） | 高亮项，默认首项 | 保持既有原始编码/日语读音提交 | 对应可见项；越界不误上屏 | 左右选择；上下翻页；Esc 清组合 |
| 组词中，引擎暂时无候选 | 不选择上轮词 | 提交当前原始输入 | 正常方案编码处理 | 不移动正文；Esc 清组合 |
| 已上屏，有可见非英语联想 | 输入普通空格并关闭联想 | 宿主回车并关闭联想 | 按可见编号选择；无该编号时输入数字并关闭联想 | 左右/上下选择；Esc 或退格先关闭联想 |

| 等待联想、当前无可见词 | 普通空格并作废在途请求 | 普通回车并作废在途请求 | 正常数字并作废旧请求 | 移动正文并作废上下文；不事后补选 |

| 剪贴板键盘导航 | 原面板规则 | 粘贴选中项并关闭 | 不当作正文联想编号 | 方向移动剪贴板；Esc 关闭 |

| 宿主拒绝提交 | 保留候选/输入，可重试 | 同左 | 同左 | 不伪成功清空 |

Shift+数字是符号，不选择候选；Ctrl/Alt/Meta 组合键保留快捷键优先级。启用的 -=、[]、,. 翻页组只在组合态分页，边界也不输出符号。编号按照显示列表 1～9、0，不给隐藏项编号，不重复编号。

## 转移与异步不变量

1. 字母/编码 → 组合；选词 → 提交成功后清组合 → 请求联想；九键部分选词仍属于组合，不能跳到联想。
2. 联想返回只有在请求代际、编辑框、语言、正文上下文仍有效且无新组合时才能展示。等待时不复用上轮可点击词。
3. 联想确认必须使用显示快照；源变化、列表重排、切换窗口、语言切换均作废旧焦点。连续联想按现有设置决定是否请求下一轮。
4. 普通空格、回车、正文移动、取消和新输入作废旧联想请求；任何导航后空格也只输入空格；迟到结果不能重新出现。
5. 提交成功后才清理选择状态。英文补全只有光标前内容仍匹配原词时才替换，不匹配不能把整词额外追加到正文。
6. 长按事件沿现有 FIFO 排队，KEY_UP 与已接管的 KEY_DOWN 对应；无候选不能吞方向键。
7. 密码/敏感输入保持不预测、不学习；语音/手写保持原会话归属，不能把识别回调当成物理候选按键。

## 已确认缺陷

- 原 HardwareCandidateNavigation 要求先导航才能用空格选联想，行为不一致；用户最新明确要求全部联想均不允许空格/回车选中。
- Enter 原始提交路径在九键使用带分词空格的 preedit，导致 `fu c k` 上屏；数字只看 onKeyDown 时的 state.candidates，不支持 associationCandidates，且存在快速输入竞态。
- 物理联想行明确关闭 showNumberLabels，显示和选择均未统一。
- NgramFusionEngine 的原分数换算在 0 两侧不连续：负分接近 1，正分除以 100，0 直接为 0.5；融合后可颠倒模型顺序。另有短上下文覆盖长上下文的学习候选合并，以及正文编辑后旧上下文残留。修复按同批 logits 作稳定 softmax，不宣称等于校准后的完整词表概率。

## 验证范围

修改后检查状态矩阵、快速事件顺序、候选身份失效、隐藏/空列表、数字越界、英文原词、模型分数平移不变性与跨零排序。构建/测试结果另在本文末尾记录。当前未打包、未安装，实际键盘交互与模型语言质量未验收。

## 手机与 Windows 的候选差异（代码确认，不等同于设备当前配置）

比较 Android 1.6.0 源码 01607542 与 Windows 当前工作目录（HEAD 13e894b1），Windows 未修改：

| 层次 | Android | Windows | 影响 |
| --- | --- | --- | --- |
| 基础引擎 | 项目维护的 Rime 原生补丁，九键过滤及附加能力 | fetch-rime.ps1 下载 librime 1.17.0 / 33e7814 官方二进制 | 同为 Rime 不代表同一解码实现 |
| 九键 | t9_filter、部分选词、原生候选策略及可选长句增强 | cyime_nine_N 以 speller algebra 映射数字，script_translator；未接入手机 t9_filter | 同样数字输入不能承诺相同候选/次序 |
| 基础词库 | tasks-chinese 固定 Rime Ice 9e66b072，部署完整方案及其依赖 | cyime.dict.yaml 组装 8105/base/ext/tencent + cyime_terms，并可追加 cyime_extra | 需要比实际部署文件/启用词库，不能只比较产品名 |
| 候选加工 | CandidateTransformCoordinator 可添加/重排插件候选；引擎词和插件文字有独立提交动作 | Runtime 获取原 Rime menu，另有 Windows 编码短语路径 | 插件、短语、过滤设置都会改变显示 |
| 上屏后联想 | ONNX 原始 logits + LCCC 公共统计 + 个人 n-gram/续词 | core/rime/learning.cpp 使用公共统计 + 个人 n-gram/续词，没有 ONNX 推理 | 候选来源本就不同；不能通过 UI 对齐解决内容差异 |
| 上下文/融合 | 近期最多 25 字；本轮修正分数、长上下文优先和正文同步 | Runtime 上下文最多 8 字；personal_weight 全集合混合 | 即使同一统计数据也可能排序不同 |
| 本机学习 | Android Rime 用户库与个人学习文件 | Windows 独立 Rime 用户库与 learning 文件 | 未同步的个人历史会产生不同排序 |
| 联想按键 | 本轮改为数字/点选确认，空格/回车放行 | Runtime 仍允许空格/数字/点选；退格/回车关闭后交给宿主 | Windows 目前未按本轮规则修改，不能宣称跨端一致 |

完整候选链：输入语言/方案/布局 → 实际引擎编码 → 分词/解码/词库权重/用户词频 → 候选过滤或短语/插件注入 → 显示快照及动作映射 → 按键/点选 → 宿主确认 → 学习及下一轮联想。拼音候选不是上屏后联想；英文补全也不是中文解码。每个阶段都应比较同一输入、同一部署数据和同一学习状态，不能拿两张未统一环境的截图判断单一排序算法。

跨端统一后续需要先统一方案/资源版本与可选能力，再使用冻结用户数据的逐键回放比较候选文字、顺序、分页和提交结果；当前没有执行跨端真实安装对照，不能声称候选已一致。

## 本轮实施与检查结果

- 物理空格/回车/数字和方向键统一进入 FIFO 后读取候选快照，去掉主线程旧列表的数字选择旁路；联想默认仅数字/点选，编号在悬浮和贴底均显示。不存在的联想编号按普通数字处理，组合候选越界仍不误上屏。
- 触屏和物理联想选择共用提交结果检查；英文上下文不匹配不再追加整词，普通文本被拒绝后保留候选。英文宿主替换仍依赖既有 InputConnection 替换接口，跨应用兼容性未验收。
- 九键原始回车去掉展示用分词空白/分隔符，保留部分已选中文；非九键使用引擎原始编码，不把展示 preedit 当编码。
- 新输入/普通分隔符/正文光标变动清除过期联想，尚未执行的 Main 队列预测也携带代际检查；宿主提交后同步光标前文本。
- 神经 logits 使用稳定批次 softmax；个人 n-gram 优先更长匹配上下文。未重训模型，没有语言质量提升幅度的实测结论。
- 主应用 Kotlin/Java 编译和针对性 JVM 检查通过：68 项，0 失败，0 错误，0 跳过。日志：`.codex-artifacts/input-state-tests-final.log`。测试包含候选导航/快照/几何、数字及原始回车、提交拒绝、翻页、退格、异步取消、分数和学习上下文。
- JVM 检查未执行原生/词库准备任务，复用已验证的语音编译依赖；未生成 APK、未安装、未提交或发布。原生解码未修改，未执行设备与跨端候选回放。真实应用交互、联想自然度及 Windows 对齐均未验收。
