# 物理键盘输入状态机与本轮修复

## 边界与事件顺序

当前实现基于已发布 1.6.1 的累计开发目录，沿用未发布批次 1.7.0。物理方向键始终移动编辑器光标并关闭候选；组词中的空格确认候选，回车提交原始编码；只有上屏后的智能联想不接受空格/回车选词，保留有效编号与点选。事件顺序为：语言/工具快捷键 → 剪贴板导航或内部表单 → 输入 FIFO → 当前编辑会话的候选快照 → 引擎/正文。不能在 onKeyDown 读取滞后的候选列表后直接决定数字选词。候选来源、显示顺序、编号、焦点和提交目标必须一致；触屏按键原有空格设置不由物理键盘覆盖。

## 状态与按键表

| 状态 | 空格 | 回车 | 未加修饰的 1～9、0 | 方向键 / Esc |
| --- | --- | --- | --- | --- |
| 非英语组词，有引擎候选 | 确认首选；九键沿用有效高亮，展开页按当前过滤列表映射提交 | 保持原始编码/日语读音提交 | 对应编号选词；没有该编号则保留原始输入并输入数字 | 先保留未确认输入，再移动正文并关闭候选；Esc 取消未确认输入 |
| 组词中，暂时无候选或快照过期 | 保留组词，不把字母串当成选词结果提交 | 提交原始输入 | 不吞数字，不送回九键解码器 | 同上，不自动选词 |
| 已上屏，有可见非英语联想 | 普通空格并关闭联想 | 宿主回车并关闭联想 | 有编号则选词，否则正常输入数字 | 移动正文并作废联想；Esc 只清候选 |
| 英文逐字上屏，有补全 | 原词加空格 | 宿主回车 | 正常输入，如 hello123；补全保留点击选择 | 移动正文并关闭补全；Esc 保留已上屏英文 |
| 等待联想或侧边隐藏联想 | 普通空格 | 宿主回车 | 正常数字，作废旧请求 | 移动正文；不选择隐藏词 |
| 空闲，无候选 | 普通空格 | 宿主换行/发送等动作 | 数字直接上屏 | 移动正文；Esc 被输入法消费，不能关闭浮窗 |

| 引擎未就绪 | 保留宿主按键路径 | 宿主处理 | 宿主处理 | 方向键直接走安全光标操作；Esc 不交给宿主 |
| 宿主拒绝提交 | 保留输入 | 保留输入 | 保留输入 | 未确认输入无法保存时不继续移动或清空 |

Shift+数字是符号，不选择候选；非方向的 Ctrl/Alt/Meta 快捷键保持原优先级。Shift+方向扩选，Ctrl+左右按词移动，Alt/Meta+方向按段落边界移动，都不发送 DPAD 焦点导航事件。启用的 -=、[]、,. 翻页组仍在组合态翻页（含此前指定的 </>）；触屏候选翻页按钮保留原行为。英文补全不显示数字编号，避免与 hello123 的数字输入冲突；非英语编号按显示列表 1～9、0。

物理移动复用 EditorCursor：优先使用编辑器 ExtractedText，缺失时使用已报告的绝对选区和周围文本；宿主不提供这些信息或拒绝 setSelection 时停住，不用 DPAD 强行移动焦点。上下方向按宿主提供的文本换行计算，无法凭文字恢复宿主的视觉自动折行；该兼容限制仍需真机验收。

## 转移与异步不变量

1. 字母/编码 → 组合；选词 → 提交成功后清组合 → 请求联想；九键部分选词仍属于组合，不能跳到联想。
2. 联想返回只有在请求代际、编辑框、语言、正文上下文仍有效且无新组合时才能展示。等待时不复用上轮可点击词。
3. 联想确认必须使用显示快照；源变化、列表重排、切换窗口、语言切换均作废旧焦点。连续联想按现有设置决定是否请求下一轮。
4. 普通空格、回车、正文移动、取消和新输入作废旧联想请求；上屏后联想无论是否导航，空格都只输入空格；迟到结果不能重新出现。
5. 提交成功后才清理选择状态。英文补全只有光标前内容仍匹配原词时才替换，不匹配不能把整词额外追加到正文。
6. 长按事件沿现有 FIFO 排队，KEY_UP 与已接管的 KEY_DOWN 对应；无候选不能吞方向键。
7. 密码/敏感输入保持不预测、不学习；语音/手写保持原会话归属，不能把识别回调当成物理候选按键。

## 已确认缺陷

- 原 HardwareCandidateNavigation 要求先导航才能用空格选联想，行为不一致；用户最新明确要求全部联想均不允许空格/回车选中。
- Enter 原始提交路径在九键使用带分词空格的 preedit，导致 `fu c k` 上屏；数字只看 onKeyDown 时的 state.candidates，不支持 associationCandidates，且存在快速输入竞态。
- 物理联想行明确关闭 showNumberLabels，显示和选择均未统一。
- NgramFusionEngine 的原分数换算在 0 两侧不连续：负分接近 1，正分除以 100，0 直接为 0.5；融合后可颠倒模型顺序。另有短上下文覆盖长上下文的学习候选合并，以及正文编辑后旧上下文残留。修复按同批 logits 作稳定 softmax，不宣称等于校准后的完整词表概率。

完整候选链：输入语言/方案/布局 → 实际引擎编码 → 分词/解码/词库权重/用户词频 → 候选过滤或短语/插件注入 → 显示快照及动作映射 → 按键/点选 → 宿主确认 → 学习及下一轮联想。拼音候选不是上屏后联想；英文补全也不是中文解码。每个阶段都应比较同一输入、同一部署数据和同一学习状态，不能拿两张未统一环境的截图判断单一排序算法。

跨端统一后续需要先统一方案/资源版本与可选能力，再使用冻结用户数据的逐键回放比较候选文字、顺序、分页和提交结果；当前没有执行跨端真实安装对照，不能声称候选已一致。

## 本次英文、数字与候选截短修正

- 英文模式的单字母直接提交编辑器，不再交中文解码器处理；编辑器接受后才累计完整英文词，供补全使用。原流程在记录 pendingEnglishText 后调用提交，普通非汉字提交又清空了该记录，导致英文补全拿不到完整词。拒绝提交不推进记录。
- 英文补全不接管数字，实体方向键始终属于编辑器。中文组合和已显示的非英语联想保留数字选词。无可选择项的物理数字直接提交，避免在九键方案下被再次解释为新编码；组合尚无候选时保留原始输入后写入数字，不把普通数字无限吞掉。
- 横向物理候选从固定三个改为最多十个，与数字选择范围一致，侧边隐藏规则不变。候选展示、编号和提交仍使用同一列表。
- 原生过滤器不再把预测匹配的中文整词裁成编码对应的前半词；保留原生候选文本、编码与提交身份。精确英文整词优先于前面的中文缩写猜测，完整中文拼音和明确非词典候选保持原优先级；没有加入 hello/fuck 的特例或重写词库。

## 本次物理 Esc、光标与 Shift 修正

- Esc 的空闲分支此前转发宿主，可能使 IME 窗口隐藏；现在组合、联想、空闲和重复 Esc 都不发送宿主退出键。输入视图被外部关闭后，再输入会请求显示，无须重新点击输入框。
- 实体方向键与浮窗触屏候选按钮分流，按键 FIFO 内完成保留原始输入、取消在途预测和光标移动，避免快速连续输入读取旧候选。未确认输入提交被拒绝时保留状态。
- 普通字符清理过期联想；有效非英语候选仍按数字选择，其余数字、数字小键盘与英文数字串按原样输入。此阶段误将组词空格也改成原文加空格，已由下述补修恢复；屏幕键盘空格设置不变。
- 补齐斜杠、分号、单引号、反斜杠、反引号这五个物理键的 Shift 映射，对应 `? : " | ~`，并核对数字行、其他标点、小键盘。非翻页键的 Shift 符号通过文字提交路径，防止被 Rime 快捷键截走。
- 最终验证：97 项相关 JVM 测试通过，0 失败、0 错误、0 跳过；主程序与 Android 真机测试源码编译通过。更新了真实 IME 测试中的数字选词、原文光标、连续 Esc、英文数字串、Shift 符号及边界焦点检查，但本轮未运行设备测试。实际 Android 交互未验收，未打包、安装、提交或发布。日志：`.codex-artifacts/hardware-cursor-20261004/validation-final.log`；逐类结果：同目录 `results.txt`。首轮过滤器误用了不存在的 RawCompositionCommitTest 类名，最终改用实际包含原始编码断言的 AssociationSelectionTest，并逐一核对 XML，未把缺失测试计入通过。
