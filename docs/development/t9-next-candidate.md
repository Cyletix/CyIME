# 九键 0：前后候选切换

日期：2026-10-02。用户指定：有拼音待选时把九键 0 改成右箭头，点按下一项、左滑上一项，只移动高亮，空格确认；空闲时仍输入数字 0。

## 行为

- 中文拼音、九键布局、键盘模式下，存在未完成编码时，0 键显示右箭头，读屏名称为“下一项”。左滑超过 50dp 且横向占优时预览“上一项”，松手执行一次；取消或越过阈值后滑回不会补发点按。按键大小、所在行列及原有上下滑配置不变；数字面板仍直接输入 0。
- 每次点按移到当前引擎候选页的下一项，左滑移到上一项。沿用引擎页内首尾循环；不直接上屏，不清空拼音、不调用引擎选词。单个候选时保持高亮，无候选但仍有编码时不产生文本。
- 空格使用点击时的高亮候选快照，沿用现有候选提交路径，包括插件候选动作、九键部分选词、词频学习和宿主拒绝提交后的处理。后续点“下一项”不会改掉已排队空格的目标。
- 输入、删除、改拼音、候选重排或注入动作变化后，旧高亮不再有效，回到首项。展开候选面板时清除本页高亮，沿用展开页原有全局索引行为。
- 候选栏记住当前可见窗口：高亮仍在栏内时窗口不动，向后越过右端时从新高亮词向前填满，使其处于最后一项；向前越过左端时从新高亮词向后填满，使其处于第一项。比如每栏能放 3 项时，`0,1,2` 选到 3 变成 `1,2,3`，再选 2 保持窗口，回到 0 才滚回 `0,1,2`。点击仍使用原候选索引。
- 窗口偏移仅保存布局历史，在成功组合后的 SideEffect 更新，不因更新偏移额外触发重组。栏高不增加，只测可见窗口及边缘附近候选；超长单项沿用原有省略显示。

这里的滚动换屏是候选栏的可见窗口变化；当前引擎页内循环保持原行为，不自动切换原生引擎页，跨引擎页查找仍使用展开候选面板。

## 实现边界

`CandidateState.candidateFocus` 保存候选列表身份与索引，`T9CandidateNavigation` 使用语言、方案、布局、模式判断，不新增 schema 字符串猜测。高亮失效判定包含引擎修订号、输入、词列表、注释和插件动作。联想结果刷新不改变正在选择的候选身份。

`ImeKeyRouter.highlightNextCandidate` / `highlightPreviousCandidate` 共用显示状态更新路径，检查输入会话可用、宿主拒绝提交状态和引擎修订。空格与普通候选点击共用 `selectCandidateAsync`；只有真正确认后才触发输入引擎与宿主提交。

UI 通过现有 `NineKeyButton` / `SwipeableKeyButton` 的图标参数显示箭头，保留同一布局容器和触摸处理。候选栏增加高亮索引与可见窗口；窗口偏移不冒充前缀，避免展开列表错误扣除已显示候选。读屏暴露候选的 selected 状态。
