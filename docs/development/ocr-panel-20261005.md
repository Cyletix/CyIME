# 键盘内拍照识别（2026-10-05）

## 用户目标

按三星键盘 Extract text 的使用方式：宿主应用留在上方，相机直接替换键盘内容区；中央识别框清晰、其余取景压暗。实时预览不保存，拍照重新识别当前中央区域，进入可编辑文本，确认后只存剪贴板，不直接提交宿主。提供取消和重拍。

此前独立全屏相机/相册页面只从剪贴板菜单进入，既难找，也不符合这次明确的流程。补入口的 20261077 Release 构建在用户补充目标后中止，未将这个中间方案正式交付。主目录仍是 `D:/GitHub/CyIME`。

## 实现边界

- 主菜单独立“拍照识别”按钮；工具栏自定义可选同功能按钮；剪贴板、智能设置与内置 OCR 模型卡进入同一键盘面板。
- 使用 CameraX 预览与分析的同一 ViewPort。处理 cropRect、旋转后，中央框与裁切共用 `OcrScanGeometry`；不是按整个传感器中心随意截取。相关 Android 文档：[预览/分析变换](https://developer.android.com/media/camera/camerax/transform-output)、[图像分析](https://developer.android.com/media/camera/camerax/analyze)。
- 相机帧采用 KEEP_ONLY_LATEST；实时识别最多约每 700ms 发起一次、最多一项在途。拍照请求等待当前识别结束，再取新画面，不把已过时的预览结果当拍照结果。
- 原生中英文模型在独立 `:ocr` 进程串行复用；不占输入命令队列。只传中央图像，关闭面板取消回调、解绑相机及识别服务；结果不经过网络。
- 识别文字放进键盘区域内的编辑卡片，复用已有内部 EditText 输入路由，普通键盘仍可修改文字；仅“确认复制”写入系统剪贴板及最近记录，不加入固定、不写宿主。
- 设置入口通过透明焦点宿主打开输入法；它不画第二套扫描 UI。系统权限请求仍遵循 Android 权限弹窗。
- 当前流程聚焦相机中央文本区域。旧独立相册识别页不再作为入口，也不在模型页继续声明“相册共用”。
