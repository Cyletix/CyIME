## 必须优先修的基础行为

### F01 · P1 · 回车／空格把显示状态当作引擎事实

证据：[ImeKeyRouter.kt:91](https://github.com/Cyletix/CyIME/blob/1.2.9/app/src/main/java/com/kingzcheung/xime/service/ImeKeyRouter.kt#L91) 异步发布；[ImeKeyRouter.kt:297](https://github.com/Cyletix/CyIME/blob/1.2.9/app/src/main/java/com/kingzcheung/xime/service/ImeKeyRouter.kt#L297) 读 candidateState；[ImeKeyRouter.kt:411](https://github.com/Cyletix/CyIME/blob/1.2.9/app/src/main/java/com/kingzcheung/xime/service/ImeKeyRouter.kt#L411) 回车判断；[ImeKeyRouter.kt:481](https://github.com/Cyletix/CyIME/blob/1.2.9/app/src/main/java/com/kingzcheung/xime/service/ImeKeyRouter.kt#L481) 空格判断。

时序：普通拼音 `a` 已进引擎 → Main 候选刷新尚未消费 → Enter 读到旧空闲状态 → 第433行清掉真实组合 → 第445行调用宿主发送／搜索等动作。空格则可能只插入一个空格，让真实编码仍留在引擎。

本地未提交的 1.2.10 已在回车分支增加 engineInput 判断和 accepted 检查；**不在正式 1.2.9 内**，也未覆盖本文指出的空格等其余入口。

修复：命令处理器维护同步领域状态，UI 只订阅它；Enter/Space 以当前引擎事务决定含义。验收：使用发布屏障延迟 UI，分别验证字母→Enter、字母→Space，含 SEND、SEARCH、普通多行框；不得误发送、丢编码或留残余组合。

### F02 · P1 · 拒绝提交保护只覆盖候选点击

证据：[ImeTextCommit.kt:216](https://github.com/Cyletix/CyIME/blob/1.2.9/app/src/main/java/com/kingzcheung/xime/service/ImeTextCommit.kt#L216) 先清引擎；第221、238行调用旧 Unit 返回值的 commitText；第222行起清 partial/UI。底层虽然有 TextCommitResult，[XimeInputMethodService.kt:2671](https://github.com/Cyletix/CyIME/blob/1.2.9/app/src/main/java/com/kingzcheung/xime/service/XimeInputMethodService.kt#L2671) 兼容包装仍把结果丢掉。

例子：有未完成组合 → 点符号／字面输入 → 先清引擎 → 宿主拒绝 prefix → 仍清显示并提交后面的符号。前段无法重试。普通引擎提交、部分 Enter/Space 路径也未完整处理拒绝。

修复：统一“准备完整文本→提交→接受后学习和清理”的交付协议，包含字面输入、自动提交、切模式及内部编辑器。若引擎已消费，保存原会话待交付文本；拒绝不能假装原生已回滚。验收：拒绝、无连接、拒绝后接受、切会话取消；确认不重复提交、不错误学习，prefix/literal 不被拆成半成功。

### F03 · P1 · 九键部分选词后切数字页会丢前段

证据：[KeyboardView.kt:1095](https://github.com/Cyletix/CyIME/blob/1.2.9/app/src/main/java/com/kingzcheung/xime/ui/keyboard/KeyboardView.kt#L1095) → [ImeKeyboardCallbacks.kt:404](https://github.com/Cyletix/CyIME/blob/1.2.9/app/src/main/java/com/kingzcheung/xime/service/ImeKeyboardCallbacks.kt#L404) → [ImeSessionController.kt:479](https://github.com/Cyletix/CyIME/blob/1.2.9/app/src/main/java/com/kingzcheung/xime/service/ImeSessionController.kt#L479)。后者只选原生剩余候选第0项，随后清 T9 及 t9PartialSegments，从未拼接 Kotlin 已选前段。

例子：九键输入多词 → 点只覆盖前半的候选 → 点 `123`。已选前半还没有上屏，却被清除；若剩余首候选仍只覆盖一段，后缀也可能消失。宿主全部返回接受也不能消除这个缺陷。

修复：切数字页、切语言、切方案必须复用同一结束组合事务，完整保留已选段与未消费后缀。验收至少包含单段、多段 partial、首候选只覆盖部分、无候选及宿主拒绝；不允许靠丢弃输入来完成切换。

### F04 · P1 · 剪贴板刷新会清掉当前拼音组合

证据：[XimeInputMethodService.kt:2062](https://github.com/Cyletix/CyIME/blob/1.2.9/app/src/main/java/com/kingzcheung/xime/service/XimeInputMethodService.kt#L2062) 的 collector 只判断近期剪贴板列表非空，就 clearComposition，并清 inputText/isComposing。

例子：正在输入但未选词 → 同步插件或系统复制带来剪贴板更新 → 当前组合与候选被剪贴板候选取代。异步首次加载迟到也可能走此路径。该修改不经过输入 FIFO。

修复：剪贴板观察只更新剪贴板状态；是否显示近期剪贴板由空闲输入态决定，外部更新不能清引擎。验收：普通全拼、T9 partial、候选展开和待重试提交期间分别注入剪贴板更新，输入内容保持不变。

### F05 · P1 · 选择与剪切使用不同的执行顺序

证据：[ImeSchemaController.kt:245](https://github.com/Cyletix/CyIME/blob/1.2.9/app/src/main/java/com/kingzcheung/xime/service/ImeSchemaController.kt#L245) 的选择／光标动作入队；[ImeSchemaController.kt:289](https://github.com/Cyletix/CyIME/blob/1.2.9/app/src/main/java/com/kingzcheung/xime/service/ImeSchemaController.kt#L289) 的全选、复制、剪切、粘贴直接操作当前 InputConnection；撤销／重做也有同步旁路。

时序：前一任务阻塞 FIFO → 依次点“选择→左扩选→剪切” → 前两项排队，剪切立即作用于旧选区 → 扩选随后才执行。结果可能剪错文字或完全没剪。

修复：全部编辑命令进入同一顺序域，同时定义对组合输入、内部编辑器和宿主选区的影响。验收用可控前驱任务，核对每个动作的实际选区和文档；还需覆盖有拼音时粘贴、替换选区、撤销、重做。

### F06 · P2 · “清空全部”实际只删光标前文字

证据：[ImeKeyRouter.kt:336](https://github.com/Cyletix/CyIME/blob/1.2.9/app/src/main/java/com/kingzcheung/xime/service/ImeKeyRouter.kt#L336) 声称清正文，实际第345行只读光标前文本，第370行只 deleteSurroundingText(before.length, 0)。

例子：无组合／联想，正文 `abc|def` → clear_all → 剩 `def`；光标在文首则不删除正文。存在选区时，该 API 也不等于删除选区及全文。

undo_clear 第381–389行只存前缀，不存文档与光标归属，并先清撤回槽、后忽略提交结果。移动光标后恢复会插到新位置，不能视作完整撤销。

修复应先定语义：ClearComposition、DeleteBeforeCursor、ClearDocument、UndoEdit 分为不同命令；显示名称与动作一致。验收覆盖文首／中／尾、正反选区、长文本、拒绝、移动光标和外部正文变化。

## 插件及工具的残留缺口

### F07 · P1 · 在途加载与禁用竞态留下孤立实例

证据：[PluginLifecycleManager.kt:123](https://github.com/Cyletix/CyIME/blob/1.2.9/plugin-core/src/main/java/com/kingzcheung/xime/plugin/core/runtime/lifecycle/PluginLifecycleManager.kt#L123) 先写 loadedPlugins，执行 onLoad，最后第132行注册 instance；卸载第51–63行仅从 instance map 查对象并关闭。

### F08 · P1/P2 · 工具面板仍有独立的执行与编辑旁路

这是一组同一组件的缺口，不能用“核心键盘已经有 owner”将它们排除：

- **P1 主线程等待插件**：[XimeInputMethodService.kt:922](https://github.com/Cyletix/CyIME/blob/1.2.9/app/src/main/java/com/kingzcheung/xime/service/XimeInputMethodService.kt#L922) 在打开面板的 UI 回调同步 getPanelState，经 LuaToolPluginAdapter 到 runtime.call；[LuaScriptRuntime.kt:65](https://github.com/Cyletix/CyIME/blob/1.2.9/plugin-core/src/main/java/com/kingzcheung/xime/plugin/core/lua/LuaScriptRuntime.kt#L65) 普通业务默认预算为180秒。慢插件或排队任务会阻塞 IME 主线程；有超时不等于这段时间不冻结。
- **P1 旧结果跨 restartInput**：[XimeInputMethodService.kt:1041](https://github.com/Cyletix/CyIME/blob/1.2.9/app/src/main/java/com/kingzcheung/xime/service/XimeInputMethodService.kt#L1041) 生成仅保存 panel epoch；[XimeInputMethodService.kt:1004](https://github.com/Cyletix/CyIME/blob/1.2.9/app/src/main/java/com/kingzcheung/xime/service/XimeInputMethodService.kt#L1004) 结果提交直接用当前连接与旧选区。严格触发条件为不经 onFinishInput 的 restartInput：编辑器重建状态使 editor session 改变，却没有对应 panel owner 校验，旧生成结果可能覆盖新正文。正常 finish 会清面板，不声称所有切框必现。

## Unicode 与光标边界

### F09 · P2 · “单字”在两个候选区域含义不一致

[KeyboardView.kt:511](https://github.com/Cyletix/CyIME/blob/1.2.9/app/src/main/java/com/kingzcheung/xime/ui/keyboard/KeyboardView.kt#L511) 用 codePointCount==1，[ExpandedCandidatePager.kt:72](https://github.com/Cyletix/CyIME/blob/1.2.9/app/src/main/java/com/kingzcheung/xime/service/ExpandedCandidatePager.kt#L72) 却用 UTF-16 length==1。`𠮷` 是一个补充平面汉字、两个 UTF-16 单元，因此上栏接受、展开正文排除；不在上栏可见前缀时会找不到该候选。

修复：共用明确的单字判断，覆盖 BMP 与补充平面汉字；正文与候选栏应使用同一个过滤后来源和索引。

### F10 · P2 · Emoji 退格损坏联想上下文缓存

[ImeKeyRouter.kt:984](https://github.com/Cyletix/CyIME/blob/1.2.9/app/src/main/java/com/kingzcheung/xime/service/ImeKeyRouter.kt#L984) 先更新联想上下文，PredictionManager.deleteLastChar 用 dropLast(1)。`a😀` 变为 `a\uD83D`，留下孤立代理项。

**这不是说宿主正文一定损坏**：宿主退格走系统 DEL。缺陷在输入法自己的预测上下文与宿主实际文本脱节。修复应根据编辑结果同步上下文，并明确 Unicode 单位，测试代理对、变音组合、ZWJ emoji。

### F11 · P2 · “向上／向下”没有按视觉行移动

[EditorCursor.kt:238](https://github.com/Cyletix/CyIME/blob/1.2.9/app/src/main/java/com/kingzcheung/xime/service/EditorCursor.kt#L238) 只识别文本中的显式换行。一个自动折成多行的长段落中，向上直接到段首、向下到段尾；编辑面板还另有段首／段尾按钮，所以这不是合理的同名替代。

修复：区分视觉逐行、段落边界、全文边界和水平字符导航。宿主能提供视觉行移动时使用它；不支持时明确能力边界，不让箭头偷偷变成段首尾。需要真实自动折行 EditText 与 Compose 输入框验收。

## 待定向验证，不计入确定缺陷

- 候选 DOWN 在旧词、列表更新、UP 时，TolerantClick 使用更新后的 callback；需定义并验证一次手势绑定哪个候选。当前不把它报成已经实测的候选错选。
- 部分编辑器对 composing region、选区替换和剪贴板动作的约定不同；静态旁路问题已确认，具体宿主覆盖结果仍须集成测试。
- 外部语音、手写、插件结果与手动编辑交错需要扩展测试矩阵。本轮没有声称这些路径已全部审完。
