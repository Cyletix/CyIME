# 漏打重复字母的纠错（2026-10-21）

用户反馈：chenggong 要连按两次 g，常打成 chengong，而 chengong 严格读出的 陈宫、臣工、陈公 平时用不到，成功 却要翻页。要求按一类问题处理，不点名加词：第一位永远给严格按所打拼音读出的结果；只有严格读法都很生僻、相近读法是很常用的词时，才把常用词放到第 2～5 位。

## 规则

- **识别**（`librime` `algo/syllabifier.cc`）：两个音节交界处，前一音节末尾和后一音节开头是同一个字母、却只打了一次时（ng+g：chen|gong → cheng'gong、xian|guan → xiang'guan；n+n：ji|nian → jin'nian），把“少打的那个字母”补在前一音节末尾，作为一条纠错音节边。如果打出的字母本来就能在同一位置读出这个音节（a 作 an 的首字母简拼），就不加，免得把简拼变成全拼。
- **门槛**（`gear/script_translator.cc`）：纠错得到的整串词，只有比严格读法自己的最佳词常用 20 倍以上才列出（成功 是 陈宫 的 9600 倍；今年 只有 几年 的 2.9 倍，不列）。这个门槛对邻键纠错、字母互换纠错同样生效，是统一的一条规则。
- **第一位**：整串词里严格读法排在纠错前面（原有 PreferCodes）；整句由“只在不含纠错的句子里选”保证；Rime 只造出一句且是纠错句时也重造不含纠错的句子（`T9PhraseBeforeSentence.cmake` 的 lone_correction）。
- **开关**：方案键 `translator/cyime_doubled_letter_correction`，雾凇系列 26 键开启（`tasks-chinese.gradle.kts`），九键、14 键、双拼不开。

## 结果（电脑同源引擎，邻键纠错开）

- 公开集、调参集 26/14 键全套回归：各列不变。
- 常见的 120 个“音节交界重复字母”词，把重复字母去掉一个当输入：首位变化 0；新出现 50 个，例如 chengong→成功 第 2、dianao→电脑 第 2、xianguan→相关 第 5、pinguo→苹果 第 4、guangao→广告 第 2、nengou→能够 第 2；被门槛挡掉 55 个，例如 jinian（几年／纪念 常用，不出 今年）、henan（河南，不出 很难）、change（嫦娥，不出 唱歌）、yanguang（眼光，不出 阳光）、aniu（阿牛，不出 按钮）。
- 逐键 p95：1180 句公开全拼，安静时两轮 +1.2%、+1.5%。

## 给 Windows 的同一规则

音节交界的重复字母只打一次时，把它补回前一音节当纠错；纠错词只在比严格读法的最佳词常用 20 倍以上时列出，且永远排在严格读法后面；这个 20 倍门槛也用于其他纠错（邻键、字母互换）。

## 纠错标注

纠错来的候选在拼音注释位置标出怎么改的，正常候选不变：多打的字母红色划掉，少打的红字补上，打错的划掉并在右上角写正确字母，打反的两个字母按正确顺序标红加下划线。

- 引擎：`Phrase::correction_marks()` 沿候选实际走过的音节图路径，逐音节输出“实际敲的=正确拼音”（纠错音节）或“实际敲的”（未纠错音节），空格分隔；路径上没有纠错边时为空。安卓经 JNI 的 `RimeCandidate.correction` 传到候选栏。
- 对齐：`CorrectionMarks.align` 对每个纠错音节做相邻交换算一步的编辑距离（插入、删除、替换、交换各 1），回溯得到保留、多打、少打、打错、打反五种标记。纯函数，Windows 按同一规则移植，例子见 `CorrectionMarksTest`。
