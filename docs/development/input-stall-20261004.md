# 偶发输入停摆与首键卡顿排查

日期：2026-10-04；工作目录 `D:/GitHub/CyIME`。属于当前未发布的 1.7.2 / 20261076 修复批次，不另行累计升号。

## 目标与证据边界

打字不能因输入框重新激活、后台剪贴板通知或单次动作异常而长时间停止。保留原选词、提交与数字规则，不能通过丢弃排队按键、强制上屏字母或重试已提交文字来制造“恢复”。

本轮读取了已连接 SM-X800 当前进程日志，没有操纵用户输入框、启用详细文字日志或清除设备日志。日志快照在 `.codex-artifacts/input-stall-device-logcat.txt`，不纳入 Git：

- 22:27:21 主线程报告跳过 93 帧，22:44:16 报告跳过 67 帧。
- 22:11:42 系统明确报告 IME 服务泄漏 `InferenceClient` 的 ServiceConnection；栈来自联想模型初始化绑定。
- 22:18:09 有推理进程 `DeadObjectException`。

上述说明进程存在真实卡顿和连接生命周期问题，但没有捕获用户本次“按键不出字”的完整现场；同一进程也承载设置界面，跳帧日志不能直接证明发生在输入按键时。不宣称已找到唯一根因，不以这些日志证明所有机器上的停摆均已复现。

## 本轮修改

1. **输入框激活不再在主线程切换／重载词库。** 原 `onStartInput` 在方案相同时仍调用 `switchSchema`，而切换使用全局引擎阻塞锁，并恢复多个选项。现在先显示已有布局，再将引擎准备放到与输入相同的 FIFO；同方案只清理旧组合并恢复选项，不重新选择方案。必须切换时，后续首批按键等准备完成再按原顺序处理。
2. **焦点变动后的操作仍受原会话约束。** 后台准备发布到 UI 前重新验证会话；旧输入框任务不能修改新输入框。结束输入时的组合清理也排入 FIFO，不再因为主线程拿不到锁而静默跳过。保留 restarting 时不切换数字／符号页面的规则，以及数字输入框自动布局。
3. **剪贴板通知不再清空正在打字的状态。** 原监听器在剪贴板文字列表变化时可以调用 `clearComposition` 并替换候选。现在组词、英文词输入或存在待执行按键时不展示剪贴板建议；通知本身不再操作引擎组合。
4. **输入动作异常不会作为未捕获协程异常终止进程。** 输入队列为普通异常设置报告边界，后续动作继续执行；过期会话的 CancellationException 仍按取消处理，不冒充成功，也不重试可能已提交的文字。
5. **推理连接不持有短命 IME Service。** 共用模型引擎改用 applicationContext 绑定，服务引用与绑定状态保持线程可见。这里只修正日志已确认的宿主连接泄漏，不能据此宣称推理进程死亡原因已解决。
6. **增加默认可记录的慢输入诊断。** 输入队列分开记录等待／执行耗时，引擎锁记录等待／持有耗时，超过 100ms 写警告。编辑器激活时每 250ms 至多挂一个主线程心跳；超过一秒未应答，记录一次该次阻塞的主线程和输入线程堆栈。没有逐键文字、候选、剪贴板内容或网络上传，结束输入／销毁时停止心跳。

相关实现：`EditorInputPreparation.kt`、`EditorEnginePreparation.kt`、`InputCommandQueue.kt`、`InputStallWatchdog.kt`、`XimeInputMethodService.kt`、`InferenceClient.kt`、`RimeEngine.kt`。
