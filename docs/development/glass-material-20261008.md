# 玻璃材质与真实透底

2026-10-08。用户要求玻璃作为适配所有配色的效果层，并在背后应用画面改变时真实透出变化。之前的实现复制黑白主题、固定三色渐变，普通键盘在不透明位图上叠黑白遮罩，不能证明或实现跨应用透底。

## 本轮契约

- 配色与玻璃开关独立，切换配色保留开关以及浅色、深色参数；关闭玻璃恢复所选配色。
- 旧内置玻璃主题只迁移一次独立开关；旧 ID 作为隐藏兼容配色保留，默认解析黑白配色，已有自定义 YAML 颜色继续保留。之后关闭玻璃不会因旧 ID 再次开启。
- 背景透明度只作用于材质背景，文字和图标保持原有颜色与不透明度。背景来源不能替换为固定截图或渐变假象。
- 系统模糊只覆盖实际测量的键盘区域，保留父输入法窗口、触摸范围、尺寸与布局。无系统模糊时保留真实透底。
- 同一窗口内替换面板不重复叠加背景，也不能透出被替换的字母键。

## 实现依据

`Window.setBackgroundBlurRadius` 对整个 DecorView 的范围生效；AOSP 的 `updateBackgroundBlurCorners` 只从背景轮廓读取圆角半径，不读取其矩形坐标。因此不能给全屏输入法窗口设置一个小轮廓后宣称模糊已限定在键盘内。

本轮使用公开的 `TYPE_APPLICATION_MEDIA` 子窗口，位于父 IME 后方，不接收输入、不获焦。它按实际键盘矩形定位并调用系统背景模糊；Compose 保留主题材质和前景。隐藏输入法时移除子窗口，不能在屏幕留下模糊块。变更区域和参数相同时不重复更新窗口。

启用期间监听公开的跨窗口模糊能力；系统不可用时移除模糊子窗口，设置页禁用模糊滑杆但保留参数，仍使用真实半透明材质。关闭、隐藏和销毁时注销监听。背景透明度不再通过黑白遮罩模拟；文字、图标不参与背景透明度。替换面板复用根背景，并依据同一展开进度只裁掉被覆盖的旧内容，保留布局测量与交互。

来源：[Android 窗口模糊](https://source.android.com/docs/core/display/window-blurs)、[DecorView](https://android.googlesource.com/platform/frameworks/base/+/HEAD/core/java/com/android/internal/policy/DecorView.java)、[WindowState](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/android12-release/services/core/java/com/android/server/wm/WindowState.java)。
