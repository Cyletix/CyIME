# 开发与交付审查（2026-10-04）

这轮反复返工的主要责任在 Agent：经常把一句局部要求直接映射成代码，缺少对用户目的、已有约束和关联界面的维护；又把编译或算法测试通过当成了足够的交付证据。下面区分对话中已经发生的错误、源码或日志能确认的原因，以及尚不能下结论的部分。

## 用户真正要求的工作方式

用户提出改动，是为了让整个输入法更好用，而不是让某一段代码符合一句孤立的描述。例如“对齐”意味着切换页面时同一位置的控件不跳动，视觉比例、触摸区域及操作含义连续；“常驻”意味着再次点开能够迅速开始说话；“只用数字选联想”意味着联想不能妨碍正文输入，并不意味着中文组词的空格也失效。

期望流程是：理解目的和旧约束 → 检查完整关联链 → 实施 → Agent 自己验证 → 自动交付到设备 → 用户体验判断 → 明确要求时发布。实际多次变成：局部修改 → 单测/编译 → 写“未验收” → 用户催打包安装 → 用户发现显而易见的回归 → 再局部修改。用户承担了本该由 Agent 完成的集成检查和交付调度。

理解目的不等于擅自替换用户方案。明确提出的工具栏尺寸、底排对齐、方向键行为等仍是约束；遇到数学上或平台能力上确实不能同时满足的要求，应指出具体冲突并给出最小取舍，不能暗中牺牲其中一个，再声称都做到了。

## 不能未经证据下结论的部分

- 语音重新打开约等 5 秒是用户报告的真实体验，但仅凭这段对话不能断定模型被释放。还可能涉及进程重建、录音启动、识别会话准备或错误的就绪门控。应分别测量点击、模型就绪、麦克风开始、首帧音频和首次识别，并用同一次关闭重开复现；不能以“有缓存字段”证明即点即用。
- 联想语序和跨端候选质量不能靠 UI 修复或几条英文示例宣布解决。Android/Windows 的引擎、词库、过滤、个人学习和联想链本来就有差别；已有状态机报告对此有代码证据。必须使用同源资源、冻结学习状态和代表性语料比较。基线也有错不等于通过。
- 没有逐次耗时记录，不能把所有慢都归因于网络或 ADB。1.7.1 已记录的完整构建为 6 分 36 秒；安装本身无需重新做这段工作。同源码重复构建、默认构建双包、反复排查入口会额外浪费时间。

## 自动脚本具体问题及本次处理

1. **入口漂移**：主目录缺少入口，临时脚本写死旧工作树、JDK、设备和签名配置来源。本次快进同步主目录至发布后的 `1044aef6`，迁回本轮修改；本地 `cyime.integrationRoot` 明确指向主目录，不凭版本号或更新时间猜目录。旧版单独修改过的版本名保存在 Git stash 和 `D:/CyIME-Data/workspace-recovery/20261004-main-sync/`。
2. **把提交号、缓存当源码变化**：旧指纹包含 HEAD、绝对工作路径、Python 缓存和同步测试的 bin/obj；提交同一份代码也会重建，生成缓存还能阻塞发布。现在构建身份按实际文件内容和构建环境计算，提交来源单独记；排除明确的生成缓存和交付控制脚本。同源码提交及缓存出现有回归用例。
3. **回执只接受当前 HEAD**：先验证 APK、再提交源码时，旧回执会因提交号变化失效。新构建记录内容指纹，保留实际构建提交；不能把旧回执改写成“提交后重新构建”。迁移已验证包保留原回执和额外验证记录。
4. **发布强制双包**：`--publish` 原来总构建 standard/full，和“只发轻量”冲突。现在默认只发所选轻量版，`--both` 才请求双包；先草稿、上传核对全部所需资产，再公开。不替换已公开版本和冲突资产。
5. **设备没连就整条停掉**：默认无已授权设备时先完成包，记录 `INSTALL-PENDING`，重试按同源指纹复用；不装到未知设备，不卸载清数据。多设备仍需明确目标。
6. **缺少便宜的真实诊断入口**：增加 `auto.cmd --check`，检查实际版本、SDK、Java、签名配置、依赖及设备，不构建或下载依赖；增加 `--install-only` 明确安装该版本现有校验包，不冒称包含尚未构建的改动。无参数依旧是当前源码打包并安装。
7. **同一个交付序号可被不同源码复用**：旧测试甚至要求同版本改源码后重打。现在已记录 v2 指纹的同一 versionCode 若源码不同会提前停止，要求 Agent 维护下次序号；不把升号责任推给用户。

SSH 地址和缺失原生插件的检查此前已经加进脚本，本次确认其现状，不把它们冒称为刚刚全部新修好的问题。所有模拟测试都仍不等于重新执行 Gradle 或公开发布。

## 从现在开始的一轮流程

1. **理解和定位**：在主目录读取相关实现，用简短说明确认想改善的体验；提取前文和图片中不能破坏的关系。除实质缺失信息外，不让用户反复回答。
2. **建立相关范围**：尺寸用跨面板几何关系，输入用状态矩阵，主题用组件及状态清单。先指出最可能退化的场景，再动代码。
3. **实现与自查**：用共享能力维护相关一致性；运行必要的契约测试、编译和有针对性的实际界面/交互检查，发现失败继续修。按原始目标判断，不用“局部看起来合理”替代。
4. **默认交付**：Agent 维护版本和序号，在 `D:/GitHub/CyIME` 使用 `auto.cmd` 生成轻量正式测试包，覆盖安装已授权设备，保留数据，核对 APK。连续补充要求合成一轮，不每改一个文件就重打。
5. **准确报告**：给包的位置、已安装设备和 Agent 实际验证的结果。只对未完成的真实部分写待验收；用户负责体验决定，不负责代跑编译、找包或指挥 ADB。
6. **明确要求才发布**：按功能提交、推送，核对源包对应关系，按请求选择轻量或双包并发布，回读链接和资产。不能因为默认安装而自动公开。

纯审查、文档和交付脚本改动不修改应用二进制时，不升应用版本、不为了走形式重打 APK。当前公开包继续是 1.7.1 / 20261075，不覆盖已发布内容。
