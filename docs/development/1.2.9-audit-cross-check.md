## 需要单列的两项，避免埋在“以后重构”里

1. **纯查询仍消费提交事件。** 对方正文已提到，但没列入 B01–B13。当前新增 readQueuedComposition 名义上是读取快照，底层 nativeGetComposition → getComposition 仍调用 get_commit（rime_jni.cc:383）。applyComposition 只处理显示，未使用 committedText；新 updateUI 还允许取消及拒绝过期结果。如果读到了待提交事件，该事件不能随显示快照丢弃。必须先分离 peekSnapshot 与 CommitEffect，再允许取消/合并显示刷新；“加锁+版本校验”不能解决副作用归属。这里确认的是调用契约缺口，完整用户触发链仍需注入 pending commit 验证。
2. **Release 日志不止耗时，也包含文字。** t9_log.h:87 的 T9_DICT_LOG 只判断 Android，MemorizeEntry 在 t9_processor.cc:767 输出 text/pinyin/digits。关闭 T9_ENABLE_VERBOSE_LOG 不会关掉它。后续诊断应默认不记录正文，统一编译门控；本次未读取或外发设备聊天日志。

## 修复顺序与关闭标准

1. 先处理副作用正确性：B01 撤销不能删词；B07 只有宿主 Accepted 才驱动对应学习/统计；B06 保留真实 code 和真实写入结果。使用临时词库、拒绝提交的假连接，不损坏用户词库。
2. 输入顺序与身份：B03 离散 DeleteOnce FIFO + Repeat 生命周期；B04 命令创建、执行、Main 提交均绑定 session；B05 点击携带 revision/handle；B02 Full/Partial 与 Rejected/Unavailable 分开。连同纯查询/CommitEffect 契约一起改。
3. B08 空筛选显示与点击同源；B09 插件开关统一来源；B10 可终止执行及有界卸载优先于把更多任务交给插件。
4. 再做 B11/B12/B13 的 runtime 代际、真实加载结果及事件协议，移除关键输入链同步脚本等待和 Release 明文诊断。
5. 用 Release 等价、固定输入序列、同设备多轮测量验证；现有测试没有覆盖 DDA/DAD、拒绝提交、partial undo 用户库不变、插件忙循环卸载等场景。补契约测试后才能关闭对应项。
