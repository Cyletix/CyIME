# 仓颉五代，2026-10-30

用户很早提过要仓颉，一直没做。这次加一个内置方案 `cyime_cangjie`（仓颉五代），默认不启用，在「已安装的方案」里打开。走注音、笔画同一条路：方案随包，码表构建时下载。CyIME Windows 同时加了仓颉，用同一张码表、同一套规则（Windows 仓库 `scripts/import-cangjie.py`）。

## 怎么做的

- 方案 `app/src/main/assets/rime_chinese/cyime_cangjie.schema.yaml`，写法参照 rime-cangjie 的 `cangjie5.schema.yaml`：table_translator，整句、自动造词照旧；不带 luna_pinyin 拼音反查（CyIME 不带，键盘也打不出 `）和「常用/增廣」开关。方案名用 `cyime_cangjie`，不占用户自己导入的 `cangjie5`。
- 码表 `cyime_cangjie.dict.yaml` 由 `app/build-logic/tasks-cangjie.gradle.kts` 生成（同 `tasks-stroke.gradle.kts`）：下载 Jackchows/Cangjie5 `c9b64e77` 的 `Cangjie5.txt`（MIT，五倉世紀版按官方手册校订），校验 SHA-256。去掉部首、笔画、兼容汉字（长得像字、码位不同，上屏会是别的字）；扩展 B 起的字只留通用规范汉字表里的（安卓字体显示不出其余的）。
- 字频：上游靠 essay.txt，CyIME 不带。每个字取两者的大者：小麦注音 `phrase.occ`（台湾语料计数，MIT，与注音同一提交 `18e2060d`），和雾凇 8105 字频（`app/data/rime_ice_8105_weights.tsv.gz`）按「的」折算到同一量级。所以简化字按大陆用量排（ommi：会 在日文 伝 前面）。两边都没计数的字按码表原顺序排在后面（z 符号码也保持原次序）。2–5 字、计数不少于 5 的词约 6.1 万条不写编码，由 librime 按构词规则编（我們 = hioan）。
- 简繁：码表是繁体，跟「繁体输出」设置走。设置关（默认）时 simplifier 用 `opencc/cyime_t2s.json` 转简体；设置开时出繁体。`ImeKeyRouter` 在同步 `traditionalization` 的地方，对仓颉反向同步 `simplification`。`cyime_t2s.json` 是 OpenCC `t2s.json` 去掉会转出方框字的 `TSCharactersExt`，加旧版 OpenCC 需要的 `segmentation` 字段。
- 键盘：xime.yaml 的 `keyboard.qwerty_cangjie`，26 键排列，键帽是字根（日月金木…，z 是「符」），点按送字母码；上下角标走 26 键的同一张表（QwertySwipeSymbols），不单配。编码栏、候选注释显示同一套字根。中文码表选了别的字母排列（Colemak 等）时仓颉跟着用。
- `InputScheme.CANGJIE`（语言中文、布局 26 键）；个人短语不挂（短语的拼音码在仓颉里是别的字的码，会抢到码表前面）。
