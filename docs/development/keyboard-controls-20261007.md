# 符号底栏、清空方向、Shift 与26键符号编辑

## 用户目标与边界

平板符号页的分类栏与两侧功能键等高，但分类与执行动作必须能区分；删除键清空/撤销和普通角标使用同一方向设置；普通主题也能看出 Shift 状态；26键符号编辑独立于拼音/双拼方案，固定字母位置，不生成新的布局。

保留工具栏、26键底排权重、长按连续删除、横滑清除组词、手写清除笔迹的作用范围、用户主题与旧布局绑定。默认未反转时下拉触发上方符号，因此同样下拉清空、上拉撤销；开启反转则相反。顶部“清空”仍是逻辑上方槽，与字母角标的含义一致。

## 原因与修改

- `SymbolKeyboardLayout` 的分类行单独 `minOf(maxHeight, 72.dp)`，功能键却填满底排。删除高度上限，沿用26键底排权重和按键内缩；中间使用连续分类条、选中下划线，与两侧独立功能键区分，窄宽度横向滚动。
- `SwipeableIconKeyButton` 原来不读取方向设置。仅清空/撤销调用点显式接入共通映射，覆盖26键及分体、九键、笔画、数字、常用符号、候选侧栏和手写；物理方向提示、回调和整键红/蓝反馈一起交换。重复删除及横向动作不变。
- `shiftKeyColors` 原来对非毛玻璃主题直接返回旧的轻微变暗色。现在普通/毛玻璃均有持续状态色，单次和锁定强度不同，锁定保留圆点；低对比强调色通过明暗混合提高辨识度并保留色相，图标保持至少3:1对比。用户设置完全透明的键仍透明。
- 原有 `QwertySwipeSymbols` 已按语言保存上下角标，且由26键各方案共用；没有必要创建另一套布局。复用 `QwertySymbolEditor`，从“布局管理 → 26键 → 编辑符号”或“布局与显示 → 26键 → 字母键滑动符号”直接进入。固定字母键只可选中编辑符号，无拖动/合并，保存不经过 `CustomKeyboardLayouts.save`。原自定义布局管理继续保留。退出未保存编辑需明确放弃。
- 实际保存回读发现旧功能失效：`QwertySwipeSymbols.load` 的 `buildMap { for (key in keys) }` 中，`keys` 解析成正在构造的空 Map 的键，未遍历对象的26个字母。写入与“已保存”提示正常，但每次读回空映射，键盘和重开的编辑器均丢失修改。明确引用 `QwertySwipeSymbols.keys`，增加真实 SharedPreferences 保存/重开/跨方案检查及空字符串关闭符号的回读反例。
