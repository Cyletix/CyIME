# 实时尺寸调整与纵向间距（2026-10-04）

## 18:27 安装反馈后的现行规则

用户对照 `1000756529.jpg` 和 `1000756519.jpg` 指出：新版首排下移、底部留空、键帽变矮而行缝仍大。此前用固定最小面板限制所有宽度的键高，再把压缩行距剩余的高度转成顶部空白，是这一回归的直接原因。下文“初版”和“行距减半”记录为历史方案，不再作为当前比例要求。

- 四行键区取消算法生成的 `topSpaceDp`、`bottomSpaceDp` 和 `extraInsetY`，首末键帽只保留半个基础键缝及既有 8 dp 底部内边距。用户设置的底部留白、导航安全区和悬浮移动条仍由各自容器处理；不清除用户配置。
- 行距只随实际单位键宽变化，宽度增量保持原来的 50%；拉高不再增加行距。显式自定义间距保留，极矮键区仍限制自动间距占比以避免挤掉键帽。水平间距沿用原度量，防止只调高度却改变横缝。
- 键帽使用真实行高，撤销固定手机最小键高乘 1.5 的饱和上限。常用平板尺寸恢复近方形键帽，手机正常尺寸仍为 56 dp 行格、约 50.5 dp 键帽。默认尺寸推导改用实际渲染同一入口，避免“默认计算是方键、实际绘制是扁键”。
- 26/14 键、九键与数字页、符号底栏、候选展开侧栏及 1:1 吸附继续使用共享度量，统一更改上下边界。原工具栏高度及拖动尺寸范围未改。
- 极窄且很高的手动尺寸仍受原有外框比例保护，本次未新增高度限制。因此继续拉高会增高键帽，不再以大块空白填充；不能同时宣称保留旧的“最高 1.5 倍键高”约束。已询问用户是否在极端比例处限制继续增高，未收到选择前不新增拖动限制。

验证：66 项相关 JVM 检查通过，0 失败、错误、跳过；主应用及 Android 界面测试源码编译通过。涵盖首尾行边界、空间总量、手机基准、平板真实默认键帽比例、自定义间距、短键区、固定/悬浮一致、连续调整、候选/数字几何、符号网格、移动条及 1:1 吸附。首次检查发现九键横缝随高度变化，已保留原横向度量后重跑。日志及逐类结果：`.codex-artifacts/edge-aligned-keys-20261004/validation-final.log`、`results.json`。未执行设备界面测试，未打包、未安装、未真机验收；没有运行暂停的整套尺寸门禁。

## 问题与修正

上述比例补修随后已随 [1.7.1 / 20261075](delivery-1.7.1-20261075.md) 轻量包覆盖安装，实际视觉和操作仍未验收。

拖动边框时，旧实现只缩放上一次测量好的键盘图层；真实宽高直到松手才传入布局，因此拖动中看到的键位、字号和工具栏比例并非最终结果。现在固定、悬浮键盘容器直接读取同一个实时矩形，并按其宽高重新测量内容；移除图层拉伸和松手才更新布局的第二份状态，底部留白也实时更新。保存逻辑、尺寸范围和越界阻力保持原样。

原有按键间距主要随宽度变化，纵向间距达到上限后，继续增高几乎全部变成键帽高度。四行输入键盘现在共用 `keyboardGridMetrics`，拖动、正常布局及 1:1 吸附都使用该结果：

- 基准沿用已有最小面板 228 dp 扣除 44 dp 工具栏后的键区，低于该基准时沿用原有键高和间距；这不是新增最大高度限制。
- 对每行新增高度 `d`，以最小态键帽高度 `b` 计算 `b + 0.5b × (1 − exp(−d / 0.5b))`，增长逐渐放缓，最高趋近最小态的 1.5 倍。
- 增长同时受实际键帽宽度与 0.68 宽高比约束。已有最小态若更窄，不再反向缩小；只限制额外增长。采用当前可用宽度，不区分手机或平板的固定最大 dp。
- 扣除键帽和原有间距后的额外空间，初版按 55% 分给行内上下视觉留白、25% 给键区顶部、20% 给底部；根据安装后反馈，现将行距增长减半为 27.5%，保持原有键帽高度和底排视觉上下边界，压缩行距腾出的空间移至键区上方。底部留白补偿减少的半间距，避免底排漂移。用户自定义间距保留为基准，仍参与额外空间分配。各键继续以所在整格接收触摸。
- 工具栏不参与这一增长曲线，保留现有 44 dp 高度。未修改已保存的尺寸与默认窗口尺寸。

悬浮模式原先可能按 4 dp 外侧留白计算间距、实际却应用 8 dp 留白；现在先解析实际留白，再按真实格宽计算键缝，避免同样尺寸的固定与悬浮键盘出现差异。
