# 设备自动适配实施方案

日期：2026-10-01；进展更新：2026-10-02。状态：**首次启动按硬件选模型已接入；运行时仍只观察建议，未验收**。当前默认选择、硬件门槛及资源准备见 [首次模型分档实现](device-model-defaults.md)，运行时基础见 [观察阶段实现](device-adaptation-foundation.md)。原规划核对基线：`theme` 分支 `fd7334b2` 及当时未提交源码。

目标：用户默认选择“自动”，输入法根据设备条件、当前负载及已安装资源，分别调整动效、联想、语音和模型驻留。首先保证打字、删除、候选点击和正在进行的识别；增强功能使用剩余预算。适配不能掩盖解码算法的性能缺陷，也不能通过降低候选质量把性能问题算作修复。

以下保留 2026-10-01 方案正文，阶段完成状态以以上两份实现文档为准。2026-10-02 用户澄清优先完成首次初始化自动选模型，并确认 low/small、普通/base、高配/base+语音校正组合，优先使用实际内存与主频。随后提供的统一能力层指导纳入上述实现与后续规划；没有授权自动打包、安装、发布。

## 1. 先把边界定清楚

1. 这是输入法本体的运行时基础能力，不建议做可卸载插件。插件可以读取分配给自己的预算，不能自行抬高整机策略。
2. `InputProfile` 继续只描述语言、方案、布局、输入方式和后端。现有 `InputCapabilities` 是输入语义能力，不改成设备性能能力；另建 `DeviceCapabilities` 和 `EffectiveRuntimePolicy`。
3. 运行时只参考当前输入语言来筛选兼容资源，不因性能自动切换语言、方案、布局、配色、深浅模式或图标。动效简化保持主题色、按键尺寸、触控范围和可见反馈。
4. 设置保存“用户想要什么”，策略输出“现在实际能运行什么”。临时降级不写回用户设置，恢复后仍遵从用户选择。
5. 已安装、已加载、正在推理、正在录音是四件事。内置模型不等于开机全加载，预热绝不获取麦克风。
6. 本方案不引入新预测模型或新词权算法。复用已有公共联想、用户学习、ONNX 联想、手写和 ASR；候选排序与语料权重问题仍在原输入算法任务内验证。

与[语言、方案、布局架构](input-profile-architecture.md)保持独立，使用处组合两者，不把设备状态保存到输入方案中。

## 2. 当前已有能力和缺口

以下是源码核对，不是真机性能结论。

| 位置 | 当前行为 | 本方案需要解决的缺口 |
|---|---|---|
| `model/DeviceDefaults.kt` | 非 low-RAM、至少 6 GiB、至少 4 核时推荐增强；只在设置缺失时初始化炫光 | 炫光和语音二次校正共用一个粗略条件，没有运行时反馈 |
| `model/BundledModelInstaller.kt` | 当前清单为手写、`predictive-text-base`、Zipformer、SenseVoice；按静态条件选择语音是否二次校正 | 安装、默认选择和运行策略尚未分离 |
| `association/AssociationManager.kt` | 加载 ONNX 联想后 `keepWarm`；无引擎时尝试重新加载 | 必须能区分“政策性暂停”与“意外断线”，否则降级后会被立即重载 |
| `association/NgramFusionEngine.kt` | 已融合公共先验、个人学习和模型结果 | 轻量模式可以复用现有能力；不得卸载神经模型时把词频学习一起关闭 |
| `model/ModelRuntime.kt` | HOT 不释放；trim 释放非 HOT 时未以活跃引用为筛选条件；部分引用增减未走同一锁 | 不能直接把新压力信号接到旧释放逻辑；先统一所有权，保护正在执行的任务 |
| `service/VoiceRecognitionHandler.kt`、`speech/AsrSupport.kt` | 本地语音开启后预热，持有常驻后端 | 需要有限驻留和单一预热入口，防止反复绑定、重复加载 |
| `service/AsrInferenceService.kt` | 非 keep-alive 时有 60 秒空闲释放；正在退出的原生识别另行收尾 | 接入统一预算时必须保留“工作线程退出后才能释放权重”的契约 |
| `service/InferenceService.kt`、Manifest | 联想/手写在 `:inference`，ASR 在 `:asr` | 单进程内存判断不足；需要跨进程的模型账目和加载确认 |
| `ui/theme/CyMaterial.kt`、`ui/keyboard/KeyGlow.kt` | 材质主要为缓存路径/渐变；按键发光有单独绘制路径 | 先测实际帧耗时，不把当前静态毛玻璃误称为实时背景模糊 |

`BaseAssociationModel` 是内置公共先验，`predictive-text-base` 是下载/内置的 ONNX 模型；名称相近，但不是同一个资源。

历史文档 `1.3.15-material-and-models.md` 写的是 Paraformer + SenseVoice；当前安装器和 `scripts/prepare-bundled-models.py` 已改成 Zipformer + SenseVoice。运行策略以实际资源清单为输入，不能照旧文档硬编码。本次不调整发包清单；未来发包验收要核对清单、显示名称和默认选择一致。

## 3. 默认体验与设置入口

在完整设置中增加一个紧凑入口“性能与自动适配”，不新增键盘快捷菜单按钮。页面第一行是“自动适配（推荐）”，后面显示当前结果及原因，例如：

> 动效：标准；联想：base，按需加载；语音：Zipformer；二次校正：暂缓（设备发热）。

首版提供三种使用方式：

| 方式 | 行为 |
|---|---|
| 自动（新安装默认） | 分功能推荐，随负载暂时调整；无需跑分向导 |
| 节能 | 减少装饰动画、预加载和驻留；基础输入、静态按压反馈、录音状态提示保留 |
| 自定义 | 用户逐项选择动效、联想模型、语音主模型及二次校正；每项也可以选“自动” |

暂不增加容易被理解为“所有东西强制常驻”的性能模式。自定义也不能突破资源缺失、语言不支持、系统禁止动画或严重资源不足等硬约束；要显示具体原因，不假装开关仍已生效。

老人版和普通版共用这套逻辑。老人版的价值是预先准备资源并给出可用默认值；不增加首次配置步骤，也不自动开启录音。用户已关闭的智能联想、本地语音等功能不会被“自动”重新打开。保留既定的单次联想习惯，不因高配置改为连续联想。

## 4. 如何判断设备和当前状态

### 4.1 证据分三层

| 层级 | 读取内容 | 用途与限制 |
|---|---|---|
| 初始能力 | ABI、系统版本、`isLowRamDevice`、总内存、可用处理器数 | 启动时读一次作保守估计；核数和总内存不能证明模型速度 |
| 运行状态 | 系统省电、充电/低电量、热状态、可用内存、已安装资源、实际输入方式 | 事件驱动；模型加载前再核对预算，不在每个按键里读取系统 |
| 实际表现 | 活跃输入的帧耗时、按键到候选延迟、模型冷/热启动、ASR 实时率、校正耗时、峰值内存 | 校准该模型/该效果的推荐；样本不足标记“估计”，不伪装成测速结论 |

不要用 120Hz 屏幕推断 GPU 强、用平板/新机推断 CPU 强，或用 RAM 推断磁盘速度。刷新率用于计算帧预算；屏幕大小、密度、窗口尺寸仍由布局适配负责。可用内存不是本应用可独占内存，Java heap 上限也不是 ONNX/native 总内存上限。

首版不做首次启动强制跑分，不承诺整个测速在 100～300ms 内完成。优先观察实际运行；需要校准时只使用随应用提供的固定短样本，且避开输入、录音和首次部署。统计留在本地，仅记录耗时/尺寸/状态，不记录输入文本、语音内容、剪贴板或设备唯一标识。重新校准为可选操作。

### 4.2 Android API 兼容

当前最低 API 28、目标 API 35。热状态监听从 API 29 提供；API 28 和不可靠信号均保留 `Unknown`。首版只接热状态监听和省电广播，事件回调不做加载/释放；热余量预测可作为后续增强，不是必需条件。[PowerManager 官方接口](https://developer.android.com/reference/android/os/PowerManager)

不能只依赖旧 `onTrimMemory` 危急等级：Android 14 起若干 RUNNING/MODERATE/COMPLETE 等级已不再通知，`onLowMemory` 也不再调用。需结合本应用可见/隐藏、低频资源核对和模型生命周期；UI_HIDDEN 不是“当前没有语音任务”的证明。[ComponentCallbacks2 官方说明](https://developer.android.com/reference/android/content/ComponentCallbacks2)

尊重系统动画开关和时长比例，Compose 与自绘动画都要验证；单次调用 `ValueAnimator.areAnimatorsEnabled()` 只能提供系统是否允许动画的信号，不代表自绘路径已自动遵守它。[ValueAnimator 官方说明](https://developer.android.com/reference/android/animation/ValueAnimator#areAnimatorsEnabled())

不把 `NNAPI available` 当成增强资格。NNAPI 从 Android 15 弃用；已有运行库是否支持具体模型、算子和加速路径，应由实际后端验证，首版继续使用已支持的执行路径，不为这个方案替换推理库。[NNAPI 官方迁移说明](https://developer.android.com/ndk/guides/neuralnetworks/migration-guide)

## 5. 各功能分别适配

下面是拟定规则，性能阈值须在实施阶段用基线确认，不是当前已实现行为。

### 动效

按用户 2026-10-02 的要求，按键动效与炫光是独立维度，不再用 `ENHANCED` 暗含两项同时开启。当前设置与首次硬件推荐已拆分，见 [独立按键效果](device-model-defaults.md#按键动效与炫光独立推荐2026-10-02-续接)。以下动态策略仍属规划；当前观察层只产出建议。

| 等级 | 具体行为 |
|---|---|
| OFF | 无时间动画，静态按压、选中和录音指示保留 |
| REDUCED | 保留必要的简洁过渡，减少同时运动对象；炫光由独立许可控制 |
| STANDARD | 正常交互过渡，复用缓存材质；不额外开启装饰效果 |

另设独立 `keyGlow` 许可，可形成全关、仅动效、仅炫光、两者开启四种组合。首次推荐优先采用全关、仅动效、两者开启三档，用户可单独修改任一项；不能因开炫光自动开缩放，也不能因关炫光顺带关缩放。当前两个按键开关只管键帽效果，不代表已控制所有面板过渡动画。

先降低装饰层成本，再减少交互过渡；不通过一律加速动画制造突兀。静态材质只有实测有明显成本时才降绘制复杂度；继续保持颜色来源和可读性。系统关动画优先级最高。设置页和键盘共享有效动效策略，但仅对应子组件订阅，避免每次热状态变化重组整个键盘。

### 智能联想

- `LIGHTWEIGHT`：现有公共先验 + 用户学习/词库路径，不运行 ONNX。
- `NEURAL`：在上述基础上运行已选且就绪的 `predictive-text-base`；初期默认推荐仍是 base，不自动下载或杜撰另一套小模型。
- `DISABLED`：仅对应用户明确关闭功能，不把暂时释放 ONNX 写成用户关闭联想。

已安装的 small 等模型可保留手动选择；能否自动替代 base，要有同一用例集上的延迟、内存和质量证据。模型文件更小不等于效果和速度均更好。

计算以已提交上下文为入口，继续复用 `LatestPrediction` 的最新请求语义。轻量结果可以先显示，神经结果仅对仍有效的会话和请求补充；更新不得破坏正在点击的候选身份。暂停时取消排队和未发布结果，不要求不可中断的原生推理立即停机。

不能仅降低 `topK` 就宣称推理提速：若成本主要在模型前向传播，少取几个结果收益有限。优先减少重复调用、加载和与输入争抢资源。纯键盘解码、用户词权和已接受提交不能被适配层取消。

### 语音

将决策分为“主识别器”“二次校正”“加载方式”三项，而不是一个高低端布尔值。

1. 先按当前语言和模型声明能力筛选，再按用户选择、资源就绪、内存及实测时延决策。不能用中文 Zipformer 替代不受支持的日语/英文输入。
2. 自动模式优先使用安装包已准备好且适用的主模型；设备测量合格、SenseVoice 已就绪且预算允许，才启用二次校正。手动指定主模型时，缺失或不支持须说明，不能悄悄换语言。
3. 每段录音开始时固定有效配置。新策略通常从下一段生效；暂停新的校正工作可在句段边界执行，不能中途销毁正在使用的 recognizer。
4. 校正过慢时保留主识别结果；迟到校正必须检查原输入会话和文本修改版本，不能覆盖用户已经移动光标或手动编辑的内容。
5. 开始语音的反馈要即时。如果模型尚未就绪，明确显示“正在准备”，就绪后再进入可说话状态，不能假装正在听导致开头丢失。延迟录音/有限音频缓冲若另行采用，必须单独验收，不能由预热隐式开启。
6. 录音结束、切换输入法、失去输入会话和异常退出都必须释放录音资源；模型可以短暂留存，但没有活跃录音请求时不能占麦克风。

二次校正资格评估使用固定样本的准确性和延迟；主识别实时率 `RTF = 解码耗时 / 音频时长` 是运行指标，低于 1 只说明平均能跟上，并不证明准确率合格。线程数从已有保守设置开始测量，不按 CPU 核数直接拉满。

### 手写及后台工作

进入手写再按需准备对应语言模型；笔迹跟手反馈永远在识别结果之前，不因模型加载或性能等级降低采样而造成漏笔画。压力下先停止无关联想预热。识别必须保留当前字的有效任务，旧结果不回填新字。

部署、模型安装、索引整理、同步和预热需要协调：首次只准备可用基础输入；安装/部署未完成显示真实状态，按键不积压到完成后突然执行。重试有退避、可见失败原因及取消条件，不能无限立即重试。低存储时暂停新资源安装，不删除用户学习、词库、剪贴板或语音文件来换空间。下载是否允许由独立网络/下载偏好决定，适配层不授权联网，也不在后台突然下载大模型。

## 6. 统一运行架构

```text
Android 系统信号 ──→ DeviceProbe / RuntimeMonitor ─┐
模型实际资源状态 ──→ ModelInventory               │
本地性能汇总 ─────→ PerformanceObservations       ├→ RuntimePolicyResolver
用户设置 ─────────→ RuntimePreferences           │        │
当前语言/输入方式 → InputProfile ────────────────┘        ↓
                                            EffectiveRuntimePolicy
                                                       ↓
                                        RuntimeCoordinator（串行应用）
                                        ↙              ↓             ↘
                                  动效投影       联想/手写执行器      语音执行器
                                                       ↓
                                          跨 :inference / :asr 资源账目
```

建议新增 `runtime/adaptation/` 包，首版保留四个核心职责，不构造通用插件框架：

| 组件 | 契约 |
|---|---|
| `DeviceProbe` / `RuntimeMonitor` | 前者静态采样，后者事件与有限采样；只产出事实，未知值附时间/来源 |
| `RuntimePolicyResolver` | 纯函数：事实 + 设置 + 可用资源 + 历史策略 → 新策略及原因，不读文件、不写设置、不调用加载 |
| `RuntimeCoordinator` | 单一状态所有者；处理迟滞、预算、加载/释放命令及服务回执；向订阅者发布真实有效状态 |
| 现有功能适配器 | UI、AssociationManager、AsrSupport 等执行具体变化并确认成功；不再各自调用硬件判断 |

`EffectiveRuntimePolicy` 至少包含动效级别、装饰效果许可、联想后端、语音主模型/校正模型、预热许可、驻留期限及推理并发预算。每项保存 `requested / effective / reason`，整体有版本。用户偏好只在用户操作时持久化；运行状态、资源账目与临时降级不冒充偏好。

请求模型前返回 `Granted(lease) / Deferred(reason) / Unavailable(reason)`；异步加载另有 `Loading / Ready / Failed`，不能把预算拒绝变成“模型损坏”或把未加载写成成功。每个命令带策略代际，输入相关命令另带输入/录音会话归属。旧代际加载完成的资源仍需记账和释放；结果不得发布给新会话。

### 模型所有权与预算

先改造 `ModelRuntime` 的引用与常驻语义，再接压力控制：

- 活跃任务持有租约，释放只能在最后一个任务确认结束后执行。预热/常驻是可撤销的缓存意愿，不是永久禁止释放。
- 加载、获取引用、归还引用、改变驻留和释放在同一个串行所有者内更新；真正 IO/JNI 在工作线程执行，不在主线程等待 `runBlocking` 释放。
- 跨进程分别返回实例代际、状态和实际负载；Binder 死亡使对应资源账目失效，并由受控恢复流程重建，避免重复加载或永久“已加载”假象。
- 计入加载中的峰值、活跃模型和退出中的旧模型；未收到释放回执不能把预算当作已空出。不能先卸载正在使用的模型来让新模型抢占。
- 排队预热最低优先；当前主识别/手写识别优先于联想增强和语音二次校正。关键输入和录音数据通路不与低优先级排队共用会被阻塞的执行器。
- 原生任务不能安全中断时，停止新增任务并丢弃过期结果，等待确认结束；不能只取消协程就认定内存释放。超时或失联显示真实故障，不反复启动相同失败模型。

模型目录增加实测成本资料：模型 ID/版本、支持语言、执行后端、磁盘大小、冷启动峰值、驻留占用、推理峰值、典型耗时和测量条件。磁盘文件大小不能当 RAM 占用。先用测量集制定预算，不能直接给任意 8GB 设备承诺“所有模型同时常驻”；资料缺失时禁止多模型投机预热，允许受控按需尝试。

联想暂停后，所有预测入口必须读有效策略，包括 `PredictionManager.getChineseAssociations` 等旁路。仅给设置页加开关、而初始化/断线重试继续读旧设置，不算完成接入。

## 7. 降级与恢复规则

初版静态分档仅作内存倾向：low-RAM 或不足 4 GiB 为保守；4～8 GiB 为标准估计；8 GiB 以上只代表有资格进一步测量增强，不自动授予 GPU/ASR 高档。零、缺失或异常读数视为未知。不同功能可同时处于不同等级。

| 事件 | 立即/当前安全边界处理 | 恢复方式 |
|---|---|---|
| 用户关闭功能 | 停止新请求；结束已有所有权后释放闲置资源 | 仅用户重新打开 |
| 系统关闭动画 | 停时间动画、保留静态反馈 | 系统重新允许后按用户/策略恢复 |
| 省电或低电量且未充电 | 停装饰光效和投机预热，缩短闲置缓存；不切断当前语音 | 状态解除并稳定后恢复 |
| 连续观测到输入卡顿 | 先暂停与输入争抢的联想增强/装饰工作，记录触发阶段 | 稳定观察后分项恢复；仍卡顿则留诊断，不谎称已解决 |
| 热状态 SEVERE 及以上 | 停预热、新的联想增强和新的二次校正；现有原生任务安全收尾 | 热状态下降并稳定后分项恢复 |
| 更严重热状态或资源不足以启动 | 拒绝新的重任务并显示原因；必要时按既有会话停止流程退出 | 预算/状态恢复后允许下一次请求，不自动重新录音 |
| 内存预算紧张 | 回收空闲缓存，推迟低优先级模型加载；不销毁活跃模型 | 加载前重新校验预算 |
| 键盘隐藏 | 取消不再有效的联想/预热，按输入会话状态回收 | 下次打开按需准备；隐藏不自动等于所有任务已结束 |

初始迟滞参数可设：非危急降级需两个连续观察窗口；危急事件立即执行允许的安全动作；状态连续正常 30 秒后一次只恢复一项，两次恢复至少间隔 30 秒。这些是待测试初值。模型驻留 TTL 按复用率和预算定，不把该 30 秒直接用于所有模型；沿用现有 60 秒 ASR 空闲释放作为对照基线。

观察窗口按时间和样本数共同定义。后台/空闲不计作流畅帧，单次冷加载不污染热态 P95；样本不足不主动升档。监测在键盘活跃或确有任务期间启动，无任务后停止定时采样，不新增常驻前台服务来维持“监控”。

## 8. 升级迁移

新安装默认自动，仍尊重老人版资源准备与基础可用流程。已有安装不能通过“这值刚好等于旧默认”推断用户没改过：缺少可靠来源信息的已有选择一律保留，显示“保留现有设置，可启用自动”。

新偏好记录每项 `AUTO / MANUAL`、策略版本和明确用户来源。迁移只做一次，版本升级不重置用户选择；设备/模型版本变化只使相关测量失效，不清理学习数据。正在运行的会话使用已接受的策略快照，更新后新会话采用新策略。

先在开发验证中以观察模式运行：记录“建议会怎样调整”，不真正干预，用来检查误判。正式启用后保留回退到已保存手动配置的入口，不能删除新配置后靠猜默认值回滚。

## 9. 分阶段落地

P0 源码接入清单与 P1 的只读观察基础已有实现；基线测量、完整偏好/资源/性能接入和后续阶段仍待完成，不能用本方案文档作为“已经适配”的证据。

| 阶段 | 工作 | 完成条件 |
|---|---|---|
| P0 基线与契约 | 核对所有预热/重载/释放入口，测当前资源成本，明确生命周期 | 发布接入清单、基线数据、未知项；建立固定语音/输入样本 |
| P1 策略与观察 | 设备探测、纯决策器、偏好来源、原因摘要；观察模式 | 策略单测与回放通过，不改变实际输入行为 |
| P2 动效与资源所有权 | 接系统动画/省电；收口 ModelRuntime、跨进程预算和释放确认 | 无活跃任务被释放、无重复加载；低开销效果降级可观察 |
| P3 联想与语音 | 接轻量回退、模型驻留、ASR 会话级策略、二次校正资格 | 生产调用链故障测试与下表场景通过 |
| P4 默认体验与校准 | 新装自动、升级保留、设置摘要、老人版清单验证；实机校准 | 所测设备有前后对照，未知机型走保守路径，未测能力明确标记 |

先收口已存在的多个模型生命周期，不同时重写解码核心。每阶段只改相关文件；打包和发布仍等用户明确指定，不自动恢复已暂停的尺寸打包门禁。

## 10. 验收与回放

必须测试生产连接，不只测试纯决策函数：

| 场景 | 必须观察到的结果 |
|---|---|
| 初装、没有测速记录、信号未知 | 无跑分阻塞，无虚假高档，基础输入正常 |
| 老用户选择/关闭了某功能 | 迁移不覆盖；临时策略不改偏好 |
| 8GB 设备 ASR 实测较慢 | 不因内存高而强开校正；动效可独立保留 |
| 120Hz 低算力设备 | 只改变帧预算，不错误认定 GPU 高性能 |
| API 28、34、35 | 缺少热回调/旧 trim 回调时仍可工作，无 API 崩溃 |
| 有 base、没有 base、base 文件损坏 | 分别神经增强、轻量可用、可诊断故障；不循环重载 |
| 策略主动暂停联想后再次请求/服务重连 | 不被旧初始化和自动恢复路径偷偷加载 |
| 连续输入/删除、63 字符长输入、展开候选 | 不丢键、不串序，不因策略调度拖慢；解码本身的回归仍单独负责 |
| 候选点击时轻量/神经结果更新 | 点击身份与会话归属正确，不误选或吞有效点击 |
| 模型加载过程中省电/切编辑框/切输入法 | 旧结果不提交；完成或取消后的资源账目正确 |
| 录音中发热、用户手动改字、校正迟到 | 不中途换主模型；不覆盖手动编辑；下一安全边界才调整 |
| 语音预热、未开始录音 | 麦克风未被获取；结束/异常后的通话录音占用检查通过 |
| 手写与联想/ASR 并存 | 保护当前任务，低优先级预热退让；笔迹仍跟手 |
| 子进程被回收、重复 bind、迟到加载成功 | 实例代际/租约正确，只有一个有效加载实例，无卸载后再无条件恢复 |
| 原生任务长时间不退出 | 不提前释放/重复加载；没有主线程等待，展示明确状态 |
| 省电/热状态在阈值附近反复变化 | 无频繁模型重载或动画闪变，恢复符合迟滞 |
| 后台长时间空闲 | 无持续跑分/频繁轮询，无非必要资源永久驻留 |
| 低存储、离线、缺失语言资源 | 不自动删用户数据、不偷偷下载、不替换成错误语言模型 |

固定记录：按键到可见反馈和候选 P50/P95/P99、掉帧、冷/热启动、各进程内存及模型峰值、ASR RTF/校正延迟、模型加载/释放次数、任务代际与拒绝原因。帧预算使用活动窗口实际刷新率；现有 `InputLatencyTrace` 是否覆盖完整链路须在 P0 核对，不把结束在“提交绘制”的时间冒充实际呈现。

纯逻辑与假系统事件可在 JVM 回放；生命周期要包含真实调用链和 Binder 故障注入。模拟器能验证状态与布局，不能证明手机 GPU、发热、续航或模型速度。最终用至少一台资源受限设备和一台较高配置设备做同负载对照；测试报告分列“逻辑通过、模拟器通过、真机实测、尚未验收”。

原规划只核对了源码、Android 官方接口及文档连接。后续观察基础的检查见实现文档；具体档位或性能阈值仍未经实机校准。
