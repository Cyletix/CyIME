# 26 键基础词频加入聊天口语（2026-10-18）

对比线程发现：按出现次数算，大半简拼错题是雾凇 base 词频偏书面语（hx 出“核心”不出“好像”、bg“报告”不出“不过”）。这是之前定下的“口语语料基础词频”一步，不依赖词组模型。

## 做法

- `tools/ime_lab/chat_word_counts.py`：读 LCCC large（MIT，九键线程下载的 `D:/CyIME-Data/corpus/win/lccc-large.txt`）前 800 万行，按雾凇 base + 8105 字的词频做一元最佳切分，统计每个词出现次数。只出计数，不保存或打印任何原句。结果 2,759 万词次、17.9 万个词（`D:/CyIME-Data/lexical-weights/lccc-20261018/counts-8m.tsv`）。
- `tools/ime_lab/chat_base_weights.py`：每个 base 词条新权重 = 原权重^(1−β) × 聊天计数^β（聊天计数换算到 base 总量尺度，多音词按原权重比例分摊，没出现的取 1）。β=0.5。
- 产物 `app/data/rime_ice_base_weights.tsv.gz`（6 MB），`prepareChineseDictionaries` 按词＋编码替换 base 权重，与扩展词频同一机制；匹配不到 99% 即构建失败。表要从上游原始 base 生成（不能拿已改过的再算）。

## 句尾“吧”被打成“把”（2026-10-20）

14 类句式测试里成批出现“下个月吧→下个月把、缓缓吧→缓缓把、被我说中了吧→…把”。原因有两层：

1. 单字表 `8105.dict.yaml` 从没按口语调过权：把 3.8M、吧 2.4M，而 LCCC 里“吧”是“把”的 7 倍。按 base 同样的办法（LCCC 与词组模型的混合计数，β=0.5，`chat_base_weights.py --dict 8105`）重算，写入 `app/data/rime_ice_8105_weights.tsv.gz`，构建时 `reweight("8105")`。
2. 只改权重会把句首的“把”也变成“吧”（把地址给我→吧地址给我）。造句时每个音节只取第一个单字（librime `max_homophones` 默认 1），后面的规则根本见不到“把”。补丁让造句可以看到每个音节前 4 个单字（`translator/sentence_char_homophones`，只对单字生效；把 `max_homophones` 直接改成 4 会让首字母 cfqa 出“出发去啊”），并让句尾语气词（`app/data/sentence_final_particles.txt`，吧/呗/呢/吗/啊…整类）作整句第一个词时扣 2（`translator/sentence_position_penalty`）。只看“是不是第一个词”：输入变长时这一点不变，增量造句的缓存仍然有效；曾试过“介词在句尾扣分”，在增量造句里会把句中的“把”一起扣掉，不采用。

只用于 26 键（雾凇及同族方案），九键走词组模型不受影响。改动在 `librime/src/rime/gear/poet.{h,cc}`、`script_translator.{h,cc}`，同步进 `patches/cyime-librime.patch` 和 `app/src/main/jni/cmake/RimeDictionary.patch`（干净子模块正向、当前子模块反向检查都通过）。

## 被嫌弃了／被回复了：试过、不采用（2026-10-20）

腾讯词权重修好后，“被嫌弃”“被回复”单打已对，加“了”又变成“被掀起了”“被恢复了”。原因是基础词库里有 掀起了、恢复了 这样的“X了”整词（4,802 条），却没有 嫌弃了，回复了 也只有 恢复了 的十分之一（7,353 对 74,017，而 回复 是 恢复 的近 3 倍）；组句时“被＋X了”两个词对“被嫌弃＋了”两个词，按各自权重比。

试了按语料统一估计“X了”（`tools/ime_lab/le_weights.py`：X 的权重 × 语料里 X 后接“了”的概率）：只重估已有的 3,013 条时改对 5、改错 7（wcl 完成了→我错了、我算了一下→我酸了一下），首字母和句式两列变差；再补上 37,513 条缺的“X了”时改对 17、改错 18，首字母多列变差。两种都不采用。真正区分“被嫌弃了／被掀起了”要看前后文，即 26 键的词组模型；它目前因为打 de 的 X地／X得 变差而没开（见“词组模型的少见读音扣分”一节）。
