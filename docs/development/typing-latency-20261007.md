# 连续输入轻微迟滞：缩短逐键路径

2026-10-07，工作目录 `D:/GitHub/CyIME`。用户反馈快速连按时持续慢半拍，区别于此前偶发失能/百毫秒以上停顿。目标是减少每次输入的额外等待，保留松手提交、滑动符号、长按、中文组词、实际选词的文本核对和输入会话 FIFO。

## 发现与修改

- 英文单字母本来直接提交给编辑器，但分支之前仍调用 `RimeEngine.setNeighborMap()` 并获取引擎锁。现在将该调用放在英文直接提交分支之后；英文仍按原输入队列排序，不越过前序选词或语言切换。
- 原来每个普通字符都先往返 Main 清空联想，然后才解码或再次返回 Main 上屏。现在英文在一次 Main 回调中清联想并提交；其他字符仍立即使旧预测代际失效，只有存在在途预测或已显示联想才返回 Main 清理。不能单看 `isPending` 后完全跳过失效操作，否则已经 post、尚未开始的旧预测可能回填。
- 英文输入每个字母都同步读取宿主 `getTextBeforeCursor(1)` 判断补全能力，并在同一次输入里重复读取。现在同一输入会话、同一个连接确认可读后复用能力结果，且字母先提交再执行首次探针；临时失败不缓存，重启输入、换输入框或换连接会重查。密码/终端不查询，内部编辑框按其实际本地编辑能力处理。
- 实际选候选仍经过 `replaceBeforeCursor` 的当前文本/选区校验；缓存仅是“能否读取文本”的布尔能力，不缓存正文，不替代回删前检查。保留宿主拒绝提交时不推进英文词状态的规则。
- 原诊断只报告 100ms 以上动作，无法看见持续十几毫秒的等待。增加固定 64 个动作的耗时窗口，统计排队/执行及两者合计的中位数、P95、最大值；总 P95 达 16ms 才写一条汇总。16ms 是诊断门槛，不是设备性能合格线。无输入内容、包名或网络上传；窗口不等于触摸到屏幕呈现的端到端测量。

没有修改按键手势检测、等待松手规则、按键动画、尺寸、候选算法、词库或模型。不能将这次路径优化等同于“所有卡顿根因已经确认”。

### 真机复测后的补修

第一份正式包安装后的绘制结果没有改善，不能结束为“已修好”。排查发现 `KeyboardView` 顶层用于自动收起候选页的 `LaunchedEffect` 参数逐次读取整个候选状态，未展开时也订阅每次英文前缀变化，导致外层键盘配置重组。将观察隔离为 `CollapseEmptyCandidatePage`，仅在展开时用 `snapshotFlow` 观察候选和联想是否同时为空；保留打开空页立即收起、仍有联想不收起的行为，不改变候选内容或排序。

按键缩放动画导致邻键几何逐帧回填的猜测已被真机隔离测试排除，没有据此改动动画或命中范围。系统跟踪中每帧出现 `measureAndLayout` 标记不代表每个按键每帧都重新测量，不将调用次数当作该猜测的证据。
