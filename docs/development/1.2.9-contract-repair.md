| B13 事件语义 | 文本提交有序；256 项队列满后停止接收、记录故障与缺口，已接收事件排空后发送 event_stream_failed 并停止实例。回调失败/超时也中止，不能称永久无损。新版统计订阅 typing_totals，使用按打字/粘贴分类的累计快照与计数会话 ID，合并及重载后的下一份快照可以补齐总数。 |

## 过程审计后的范围收口

本轮只收口五处，不继续扩大性能改造。审批通过不作为架构正确的证据。

1. 候选校验不比较 UI 对象引用；只追加展开页、刷新无关联想不作废原候选，列表内容/映射或引擎版本改变则拒绝。
2. 编辑器拒绝时引擎可能已经消费选择，因此恢复源是原会话的待提交文字，不能宣称“原生组合已回滚”。重试只由用户明确触发；取消会清输入态，切换编辑器则销毁旧待提交内容。
3. 普通队列、候选选择、Main 提交及 UI 发布要求原始 InputCommandOwner；publishUi 不再补建当前 owner。T9 队列从 Main 入口捕获宿主 context，另保留自身 admission/epoch 校验。缺 owner 的后台入队是契约错误。同步剪贴板、语音/手写交付仍有独立 Main 入口及各自会话校验；不声称所有输入来源、所有 JNI 调用均已统一。
4. 队列溢出测试覆盖真正 LuaScriptRuntime 的接收、排空、缺口通知和失败状态。统计插件源码及独立包需一起更新；主 APK 不会自动替换已装旧插件。累计快照不等于持久化提交日志，进程终止前未保存的数据仍不保证恢复，日/速度明细按快照到达时间归集。
5. 多段真实音节码在原生选择阶段拼接，并跨编辑器拒绝保留；选词学习不再把显示注释当编码。测试将原生部分选择、最终选择、拒绝、重试与学习连接起来。

尚未收口：两套输入队列合并、逐条提交事件的持久化重放、全语言/全宿主故障矩阵、Release 等价端到端性能目标。当前修改不能描述为“全部 bug 清零”。

## 后续：输入 FIFO 收口（2026-09-29）

本节对应“继续修复”，上节 APK 哈希及计数是上一轮基线，不能代替本轮验证。

- 普通按键、候选选择与 T9 控制器共享服务持有的 InputCommandQueue。命令等待 Main 上屏时仍占有原顺序；选词、学习、清理结束后才运行下一键。
- T9 控制器关闭只终止自身输入/回调，不关闭服务队列。独立控制器和测试仍可持有私有队列。
- 移除选词时跨队列 runBlocking 等待；部分选词后的剩余编码刷新在原选择事务内执行，不再追加到队尾。
- 九键未消耗的退格直接在当前命令内回落到服务删除处理，不再借普通按键回调重新入队。这样排在退格后的数字不会先进入引擎再被它删掉。
- 成功交付不再临时设置“提交失败待处理”状态挡键。真正的拒绝仍保留文字并要求用户重试/取消。
- 上屏后的显示清理不递增编辑会话代际，不取消已排队的下一键，也不借 Compose effect 再向队尾补清引擎。换输入框时的过期取消保持。
- 本轮不同时改候选插件异步协议；同步插件耗时与端到端性能验证仍待处理。其他生命周期/刷新入口仍需逐项迁移，不能声称所有 Rime API 已统一。

验证进行中：新增挂起提交期间连打、部分选择与后续数字顺序、队列关闭/取消及上下文传递测试。最终计数和安装结果以本节后续记录为准。

首轮新增队列测试暴露实现缺陷：对返回的 LAZY Job 执行 join/await 可以绕开消费端提前启动。现改成每个任务先等待队列发放执行许可，外部等待不再改变命令顺序；该失败保留在 `1.2.9-input-fifo-build.log`，修复后重跑。
