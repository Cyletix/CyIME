## 修改与原因

- 所有使用 `KeyFlickLabel` 的滑动预览在到达确认位置时，以普通主字符字号的 115% 为目标，仍按实际键帽与系统字号限制大小。只调整共用预览，回滑取消、松手提交、角标内容、键帽边界和工具栏不变。
- 输入方式选择页原先调用“只换布局、保留方案”的解析器，从双拼切到只装有拼音的九键时会找不到目标。现在用户点选布局后，当前语言下只有一个已安装组合就直接确认；多个组合则显示方案列表，等用户点选。不改变布局绑定或语言切换的解析规则，不凭名称拼接引擎 ID。
- 空格光标回调进入 `ImeSchemaController.editCursor` 后原先始终使用宿主应用的 InputConnection，遗漏内部文本框。现在文本、编码、工具面板聚焦时使用对应 EditText 的连接，保持字符边界和纵向移动逻辑；内部连接缺失时不落回宿主。原宿主队列里的动作也检查内部焦点，避免弹框打开后旧动作误改宿主。
- 后续截图指出缩略图随 60:40 行高拉伸。现在缩略图按固定参考比例等比缩放，较高面板的布局卡片相应加宽；所有卡片都显示预览/名称分隔线，方案卡片缩至原计算宽度约 3/4（保留最小可读宽度），小鹤双拼显示 `xn'he'ul'pb`。保持两行高度分配、竖排侧标题、工具栏及用户实际键盘高度。
- OCR 先前增加了候选“确认”按钮和整条底栏，误把“确认后关闭相机”理解为新增一步，遮挡原本就有限的取景区。现改为画面占满整个工具区，取消、拍照、相册分别悬浮；实时文字仅在顶部显示，不加结果底板。拍照确认当前稳定文字，无稳定文字则取新帧识别，成功直接进入原剪贴板样式编辑器；相册点击识别也直接进入编辑器，失败保持取景/图片供重试。中央框和裁剪统一按完整画面计算。
