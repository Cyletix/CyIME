# 整段上屏后的联想只接下一个词（2026-10-31）

## 用户反馈

新用户：打「你在吃饭莫」上屏后，智能联想给的是“莫名其妙”，和前面打的没关系。

## 原因

公共联想表 `association/lccc-base-v1.bin`（`continuation_build.cc`）只按已上屏文字最后 1–2 个字查，
而且同一行里混着两种事件：

1. 下一个词：吃饭 → 了 / 吧 / 的时候；
2. 当前词的后半截：莫 → 名其妙、我 → 们、饭 → 店（用户只打了词的第一个字时用）。

「饭莫」不在表里，于是退到只看「莫」，这一行几乎全是第 2 种（莫名、莫名其妙、莫非、莫斯科……）。
可用户是整段上屏的，「莫」已经是一个词（语气词）的末尾，第 2 种补词在这里不成立。

## 改法

- `tools/ime_lab/ngram/tag_word_completions.py` 给表里的行打标记：上文的末尾几个字加上续词的开头几个字
  能组成一个词（jieba 0.42.1 词表，两字以上），就是“补完上一个词”。标记存成新资源
  `association/lccc-base-v1.completions.gz`（每个上文一个 16 位掩码，184 KB），文件头记着所属联想表的 SHA-256，
  单元测试核对两者一致。原联想表不动。
- `BaseAssociationModel.predict(..., afterWholeWord)`：这次上屏以两个以上汉字结尾时（整句、词、语音），
  跳过这些行；如果表里只查到最后一个字（更长的上文不在表里），而这一行“下一个词”的部分不到 15%，
  这一行整体不用（莫 的剩余只有 尔/斯/瑞 这类人名碎片）。
- 单个字上屏照旧：手写、逐字选字时，莫 → 莫名其妙、我 → 们 这类补词保留。
- 神经联想模型和个人学习的候选不受影响。默认设置不变，没有新开关。

## 检查

- `BaseAssociationModelTest`：原有 4 项 + 新增 3 项（标记、越界拒绝、打包资源上的「你在吃饭莫」），
  在云端用 Kotlin 2.0.21 + JUnit 4.13.2 单独编译运行，7 项全过；`endsWithWholeWord` 的用例另行运行通过。
- 没有跑整套 `./gradlew test`、没有编 APK、没有真机验收（云端没有 Android SDK）。
- 读入多一个 184 KB 文件；PC 上 JVM 计时读入和查表与改前在同一量级（噪声大），手机上的耗时未测。
