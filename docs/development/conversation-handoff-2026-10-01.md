### 2.2 语言、方案、布局分层

状态：**已进入源码和设置界面，针对性 79 项测试及 Kotlin 编译通过；不是整个旧架构迁移完毕，没有新 APK 或真机验收。**

已统一定义：

| 概念 | 含义 |
|---|---|
| `InputLanguage` | 中文、日语、英文等自然语言；UNSPECIFIED 只是缺失元数据标记 |
| `InputScheme` | 拼音、双拼、五笔、罗马字、假名、直接输入等编码/解码规则 |
| `InputLayout` | 字母键、九键、合并布局、假名键盘、手写板等排列与交互 |
| `InputMode` | 键盘、手写、语音 |
| `EngineProfile` | 实际 Rime schema、Direct 或 Handwriting 后端 |
| `InputCapabilities` | 可编辑拼音、日语转换等输入语义能力，**不是硬件性能能力** |

产品层由 `InputProfile` 组合这些概念。schema ID 留在后端、部署、旧存储与会话身份边界，不再新增散落的字符串猜测。中文拼音 26/9/14 键属于同一方案的不同布局。

已经接入语言管理的方案/布局选择、语言切换摘要、键盘路由、分体适用范围、日语部分按键/回车/标点路径、拼音编辑能力和 14 键判断。只展示实际存在且启用的组合，不凭字符串拼一个不存在的 schema。

实现细节和兼容约束：

- `InputProfiles.describe` 是内置/已安装配置的描述；`current` 使用真实布局绑定。已加载布局文件后，不能继续拿目录默认布局冒充用户实际绑定。
- `InputUIState.inputProfile`、`KeyboardUiState.inputProfile` 从真实状态投影，不额外保存一份容易漂移的语言/方案/布局状态。
- schema 可显式写 `language: ja`、`input_scheme: romaji`；重新发现后发布新的不可变描述表。普通按键查询不做文件 IO。

### 2.3 设备自动适配

状态：**只有规划，未修改运行行为、未运行方案验收。**

完整产物：[device-adaptation-plan.md](device-adaptation-plan.md)。已加入 AGENTS 导航。用户要根据配置适配动效、智能联想、语音模型等；方案决定放在本体统一运行层，而非可卸载插件。

核心决定：默认自动，功能分别判断；初始保守估计加实际运行数据，不只看内存/核数。用户意愿和临时有效策略分离，降级不覆盖手动设置。主题色、深浅、语言和布局不随性能档位改变。

规划内容：

- 独立 `DeviceCapabilities` 与 `EffectiveRuntimePolicy`，不把硬件状态塞进 InputProfile/InputCapabilities。
- 动效分 OFF/REDUCED/STANDARD/ENHANCED，先减少装饰成本，保留静态反馈和必要交互过渡。
- 轻量联想使用现有公共先验/个人学习，神经增强使用已就绪的 base；不新增模型，不擅自下载 small。
- 语音先检查语言兼容性，再选主模型和二次校正；一句话内不换主模型，迟到校正不能覆盖手动修改。
- 统一模型加载/引用/驻留/释放和跨 `:inference`、`:asr` 进程预算。预热绝不获取麦克风，加载成功与允许加载分开表达。
- 省电/发热/内存/卡顿触发适配，带迟滞和恢复间隔；未知能力保持未知，不把高刷新率当高算力。
- 新装自动，已有配置保留；老人版只简化资源准备，不再增加首次设置负担。

现状核对发现的缺口：`DeviceDefaults` 只用非 low-RAM、至少 6 GiB、4 核同时推荐炫光/语音增强；AssociationManager 会 keepWarm；AsrSupport 有独立常驻预热；ModelRuntime 的 HOT 与 trim/refCount 契约不能直接作为统一预算基础。旧 trim 回调在新 Android 上也不能作为唯一压力信号。

计划阶段：基线与生命周期 → 纯策略观察 → 动效/模型所有权 → 联想/语音接入 → 实机校准和默认体验。**这些阶段均未实施。**

- 最终设置顺序以用户纠正为准：跟随系统/浅色/深色三张原比例预览卡恢复在前，之后配色；图标、视觉样式等装饰性入口后置。不能再次拿“一行芯片更紧凑”覆盖该明确要求。
- 键盘菜单尽量单页八项，设置在第一页；重复深浅入口和低频模型管理捷径移除，完整设置里的功能保留。极窄屏/大字可分页，不能硬挤到不可触控。
- 输入方案排序用拖动卡片、其他项连续让位和边缘滚动；松手保存，取消恢复，不能只是两个项目瞬间互换。
- 858 配色移除，旧选择迁移柔和蓝并保留显示模式。候选翻页恢复早期圆形左右箭头外观，同时保留当前对齐、等高和命中范围。
- 普通键与设置卡片不做双描边/强辉光。BASE/RAISED/FLOATING 表示材质层级，炫光是独立按压装饰。颜色从当前主题取，不能回退自创紫色。
- 手写普通/全屏/查字共用主题笔迹；当前文档记录 3.5dp、平滑连续曲线、柔和窄边和透明渐变，复杂宿主背景加窄半透明分隔。用户拒绝过粗“中”字、过细笔迹和放大锯齿图，旧“通过”结论已撤回。
- 数学基础色对比度不等于半透明最终像素对比度；Canvas 抗锯齿开关也不等于实际截图无锯齿。应使用真实 down/move/up、手机像素密度和原始分辨率看效果，不放大低密度图充数。
- 手写普通布局、全屏两排功能结构、右侧等高对齐、手机/平板比例，以及删除/回车音效与长按行为必须看实际生产组件，不能只看概念图。

自定义布局保留原 26 键其它配置；用户要求 0.3 秒长按拖动、命名/保存/继续编辑/删除、相邻合并并同步编码、主题搭配强调色。原“红色”实际意图是主题内显著且协调的强调色。

分号问题后来采用了明确空位：当前 `CustomKeyboardLayouts.kt` 的 `EMPTY_SLOT = "_"` 只供编辑器使用，`typingRows()` 会去掉空位，不自动生成标点键；显式启用分号才将空位转为 `;`。旧格式第二行末尾的分号迁移为空位。不要恢复最早“多放一个分号占位”的实现；迁移仍要核对旧数据与实际键盘。

保留的 QWJRTK 示例行序为 `qwjrtkuiop / asdfghenl / zxcybvm`，作为可编辑/删除的用户布局，删除不重新播种。最初研究的 7.16% 是双拇指模型预测时间下降，不是实测真人提速；新安装不自动部署实验布局。
