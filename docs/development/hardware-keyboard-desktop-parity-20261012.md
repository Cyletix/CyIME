# 物理键盘向桌面端看齐（2026-10-12，1.12.15）

来源：Windows 会话对比两端“选词逻辑”后转来 4 项 Android 应向 Windows 借鉴的点（用户原话：“那你就按这个做一下……不能出现倒退”）。逐项核对代码后，1.12.15 做了 3 项；第 3 项（26 键加语法模型）按数据暂不启用，见下。1.12.16 按用户决定撤回第 1 项，保留第 2、4 项。

## 1. 空格不选工具栏高亮的候选（有意与 Windows 不同，1.12.16 撤回）

- 1.12.15 曾让实体空格确认工具栏上高亮的候选（`physicalCandidateDecision` 的 `highlighted` 参数）。1.12.16 已删掉该参数，空格恢复为：组词时确认默认候选（26 键第 1 个，九键为屏幕高亮 `spaceCandidateIndex`），上屏后的联想只能用数字或点按，空格照常输入空格。
- **设计动机（用户 2026-10-12 说明，勿再按 Windows 端改回）**：Android 每次上屏后都会自动弹出下一个词的智能联想。空格若跟随高亮或选择提示词，正常打字时会频繁把联想词误上屏，以前正是为此让空格不选提示词。Windows 端没有上屏后自动联想，空格选高亮项不会误伤，所以两端在这里有意不同，不属于“Windows 较好”的待同步项。
- 守护：代码注释在 `HardwareCandidateNavigation.kt` 的 `physicalCandidateDecision` 与 `ImeKeyRouter` 调用处；单元测试 `physicalSpaceKeepsTheDefaultCandidateAndNeverPicksSuggestions`。

## 2. Caps Lock 与大写字母

- 现象：`keyCodeToKey` 只看 Shift，Caps Lock 开着时字母仍按小写拼音组字（英文模式下也打不出大写）。中文组字中按 Shift+字母，Rime 把它当小写字母并入编码，旧代码见上屏结果不是该大写字母就 `clearComposition()` 再上屏大写字母——已打的拼音整段丢失。
- 修改：
  - 物理键盘的字母键：Caps Lock 与 Shift 一样反转大小写（数字、符号仍按 Shift 本身）；日语假名输入保持原规则。中文里大写字母照原有路径直接上屏，英文模式下打出大写。
  - 中文组字中出现大写字母（Shift 或 Caps Lock）：已打的字母按原样连同大写字母上屏（`commitHardwareLiteral`，与回车上屏原文同一路径），不再丢拼音。屏幕键盘 Shift 同样受益（原来同样会丢）。
  - 组字中按 Caps Lock 键：已打的字母按原样上屏并清空组字，系统照常切换大写锁定（按键不拦截）。
- 与 Windows 的差别：Windows 把大写前缀留在组字里、之后的拼音接着转换（“ABC”+“nihao”→“ABC你好”）；Android 架构里英文字母是即打即上屏的，大写字母直接上屏后再打拼音，结果文字相同；只是前缀已上屏，Esc 不能再撤销它。

## 4. 工具栏够不到每页第 11–20 个候选

- 现象：手机每页 20 个候选（`page_size` 默认 20），物理键盘工具栏最多编号显示 10 个；上下键与工具栏箭头按 Rime 整页翻，每页后 10 个永远看不到、按不到。
- 没有改 Rime 页大小：在工具栏与屏幕键盘之间切换时改页大小会重建方案（`ApplySchema`），正在打的拼音会被清空。
- 修改：工具栏把一页显示成 10 个一组的窗口（`HardwareCandidatePresentation.window`，`HARDWARE_PAGE_SIZE = 10`，工具栏 `MAX_VISIBLE_CANDIDATES` 共用同一常量）。上下键、工具栏箭头、`-`/`=`、`,`/`.` 翻页先在本页窗口间移动，到头才翻 Rime 的页；往回翻到上一页时先显示它的最后一组（同一输入才这样，打了新字母就从第一组开始）。数字键、空格、点按都按窗口位置换算成本页位置再上屏。屏幕键盘不受影响（`isCompact` 时才分窗口）。

## 5. 工具条贴底只认底部中间（1.12.16，用户追加）

- 现象：拖动实体键盘工具条时，只要靠近底边，不论左右位置都会吸成底部通栏；想停在左右侧边靠下的位置，总被吸到底部中间。
- 修改：`HardwareToolbarGeometry.positionAt` 的贴底条件加上水平位置：工具条中心离底边中点不超过一个吸附距离（`snapDistancePx`，8dp 边距×4）才贴底。底部其余位置照常判断：靠左右边吸到侧边，否则自由停放。不贴底时把 `yFraction` 压到略小于 1，因为 `isBottomDocked` 用 `yFraction == 1` 判定贴底。拖动预览走同一个函数，所以和松手结果一致。中间悬浮吸附和“底边使用三星式通栏”开关不变。
- 与 Windows 的差别：Windows 端底部可吸附的宽度等于通栏宽度减去胶囊宽度（`ToolbarGeometry.Target`），下角保持自由停放。Android 按用户要求只认中间一点，下角吸到侧边。
