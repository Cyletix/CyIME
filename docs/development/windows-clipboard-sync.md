# CyIME Windows 剪贴板对接记录

## 2026-10-04 当前实现：内置发现与重连

Android 新增原生 Windows 连接入口，使用 Windows 现有 `_cyime-clip._tcp.` 发现、v2 固定证书 HTTPS 和逐设备令牌。打开同步页自动寻找同网电脑，不填写 IP、端口或密码；首次连接两端确认同一连接码，随后地址变化由发现自动更新。未知电脑不会在未经确认时收到剪贴板内容。二维码为可选入口，旧插件配置收在高级选项。

Windows 对应增加 `/api/pair/nearby`，在加密连接和附近发现开启时提供有时限的配对请求；请求须由本机同意，拒绝、过期和已消费请求不再发放令牌。关闭二维码不会关闭附近连接；停止同步会取消附近请求。双方仍复用既有文本同步协议和协调器，不传历史记录或图片。

当前 Kotlin 编译、Windows 构建及 Windows HTTPS 配对自测通过。Android 真机发现、两端系统剪贴板与实际局域网断线重连尚未运行；本轮未打包或安装，未验收。

## 前一实现：内置 Lua 兼容插件

正式版此前没有携带 Windows 同步插件，设置入口却要求下载；源码存在不等于用户可用。现由 `prepareBuiltinClipboardSync` 从 `plugins/cyime-windows-sync` 生成内置资源，普通版和内置模型版均包含，应用启动时经现有安装器初始化。已有安装、配置、网络授权及启停状态不覆盖，同步仍需用户主动开启。设置页随插件初始化刷新，直接显示连接说明和配置，不再要求先下载。

兼容插件使用 v1 手动连接，电脑关闭「加密扫码连接」、开启「允许手机通过局域网连接」并启动同步；其地址和配对码仅供已有手动连接保留。新连接使用上面的原生入口，支持 v2 TLS 和附近发现。仅同步文本，不同步图片和完整历史。

验证：生成资源与协议源码逐字节一致；Android Kotlin 编译通过，45 项协议与协调器测试通过、零失败、零跳过，其中互操作测试直接编译当前 Windows 服务代码并验证双向 Unicode 文本、去重、ETag 和错误响应。UI 仪器测试预期已更新，未运行。本次未打包、未安装，真实手机与局域网未验收。

## 方案

使用独立 `clipboard_sync` Lua 插件 `com.cyime.plugin.windows_clipboard`，不把 Windows 协议塞进输入命令或候选路径。复用既有插件选择、配置表单和网络授权入口，只要求填写电脑地址和配对码。Windows 已有兼容 GET/PUT `/api/clipboard` 的服务，本轮不修改 Windows 产品源码。

配置及边界见 [插件说明](../../plugins/cyime-windows-sync/README.md)。本轮没有 APK、xipk、安装或发布操作，也没有运行整套尺寸门禁。

## 已修正的对接缺口

- 原桥接器「失败退避」只会丢弃后续通知，不会自动重试；改为保留最新一条、串行推送、退避重试。
- 原来监听数据库历史写入，可能上传编辑或延迟到达的旧条目；改为读取系统剪贴板变化。
- 用输入法可见状态驱动 Windows 插件前台轮询；旧 WebDAV 保持其可见时拉取节流，不被强制改成短间隔轮询。
- 拉取结果经过本地版本/内容检查；关闭或隐藏期间的迟到结果不写回。Android 没有系统级原子剪贴板比较写入，不承诺排除外部进程在最后读写间隙的所有竞争。
- 拉取成功与写回成功分离，确认写入之后才缓存 ETag；换电脑/配对码及重启不沿用旧缓存。
- 插件异常不再经适配器变成无变化或「测试成功」；配置测试按钮也走真实测试结果。
- 新增 `host.bin.utf8`，修复 LuaJ 补充平面字符的字节长度、SHA-256 与 HTTP 请求体不一致。保留原二进制 API 语义。
- 移除通用 HTTP 桥接器的请求正文日志，避免把剪贴板文字写进日志。
- 敏感剪贴板、自动短信验证码不发送；输入法失去剪贴板访问权限时停止读取/写回该条。
