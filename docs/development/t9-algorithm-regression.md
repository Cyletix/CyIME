# 九键算法固定回归流程

日常选词测试直接在电脑运行当前仓库的 Rime、九键解码、候选排序与神经重排代码，使用现有词库、语法模型和句子模型。Windows 通过本机 WSL 执行 Linux 原生引擎；不连接平板，不依赖安装包，不运行 Android 界面，不打包或安装应用。

## 固定入口

从仓库根目录运行原聊天语料：

```powershell
python tools/ime_lab/t9_replay.py run --output .codex-artifacts/t9-host-current
```

首次运行在独立缓存内准备电脑端编译依赖及引擎；后续按源码指纹复用构建。当前机器默认 WSL 为 `Ubuntu-22.04-D`，其他 Linux 发行版可用 `--wsl-distro` 指定。Linux 上可直接用 Python 运行相同入口。需有现成 `org.json` JAR（默认查 Gradle 缓存，也可用 `--json-jar` 指定）。所有结果目录必须是新目录，防止覆盖旧证据。

每次保存原始输入、拼音、每个数字按键的候选、每个汉字读音完成时的首选、停顿后的候选和整句结果。`index.html` 为概览，`characters.csv` 为逐字明细，`report/index.html` 可检查全部按键和候选；`run.json`、`engine-build.json`、`resources.json` 保存来源和哈希，`quality.json` 保存约束结果。

对比修改前后的本机结果：

```powershell
python tools/ime_lab/t9_replay.py run --output .codex-artifacts/t9-host-after --baseline .codex-artifacts/t9-host-before
# 已有两份结果时无需重新运行引擎
python tools/ime_lab/t9_replay.py compare .codex-artifacts/t9-host-before .codex-artifacts/t9-host-after --output .codex-artifacts/t9-host-comparison
```

比较时重新核验原始数据和哈希，不信任预先生成的统计。语料、按键协议、初始个人学习状态必须一致；允许引擎、词库和模型改变，以测量改动结果。主机和 Android 的运行协议不同，不自动当作同一环境比较；跨平台候选一致性不能由本机回归通过直接推出。

## 给定新文本

准备 UTF-8 原文 `chat.txt` 和拼音 `chat.pinyin.txt`：后一文件按原文顺序给每个汉字一个完整拼音，用空格或换行分隔。标点、数字和英文保存在原文中，用来划分中文连续输入段，不送入九键中文引擎。例如：

```text
原文：你好，睡不着。
拼音：ni hao shui bu zhao
```

```powershell
python tools/ime_lab/t9_replay.py prepare --text chat.txt --pinyin chat.pinyin.txt --output chat.fixture.json
python tools/ime_lab/t9_replay.py run --fixture chat.fixture.json --output .codex-artifacts/t9-chat-new
```

支持带调字母、数字声调、ü/v 等规范化，并检查汉字数、拼音合法性、数字编码、原文位置和完整覆盖。`--auto-pinyin` 可使用已经安装的 pypinyin 生成读音，但会标记“未审阅”；多音字须核对，不能把错误读音算作输入法问题。原聊天夹具已经固定逐字读音，包括“睡不着”的 `zhao`。`--readings` 可提供按用例 ID 的完整读音纠正。

## 判定规则

- **直出**：当前汉字的完整拼音已经输入，首选与原文到该字的完整前缀相等。分别统计即时结果、逐字停顿结果和整段完成结果。半个音节的首选保留审查，不计入直出率。
- **回归**：目标候选从首选、前五、前百掉出，或名次下降；逐条保留改善与退步，不用总分改善抵消某句退化。超时、不接受按键、引擎实际输入丢字都算执行问题。
- **语言异常**：选错原文不自动等于不正常语言。已审定的异常按语料哈希、用例、按键位置和阶段精确绑定为断言；此次聊天已经保存 33 个异常时点。旧异常重现仍返回失败，即使和基线相同。新出现或改变的首选进入待审清单，审定后加入对应断言。
- **退出码**：`0` 表示采样完整且未违反已声明约束，不表示全部原文首选正确或语言自然度全部合格；`1` 表示已知异常、回归或执行问题；`2` 表示环境、输入或证据无效。

不能把测试语料或答案灌入词库、添加专门命中的权重，再称为算法通过。异常断言仅检查输出，不参与引擎选词。

## 执行边界与复现

电脑端编译使用隔离源码快照，避免现有 CMake 的插件复制和补丁步骤改动正在开发的源码。原 JNI 和候选策略继续参与计算；平台日志适配只把 Android 日志改发到标准错误。ONNX 使用支持同一 API 的 Linux 原生库，不关闭模型、不退回普通拼音引擎冒充当前算法。

词库快照取自当前源码及已经生成的中文资源，不依赖 APK。缺少必要词库、语法模型或句子模型直接失败，不自动打包。每次使用新的个人数据目录，不导入手机个人词库、不提交候选、不产生学习。原始聊天按连续中文段回放，段间清空组合；此协议测试无上下文学习的连续拼音，不模拟用户中途选词或微信上屏。

两个标准过程均逐数字调用真实引擎：连续输入在段末等候重排，逐字停顿还在每个完整音节处等候重排。默认每键额外等待 35ms，最多等候重排 5 秒；保存实际耗时和模型状态。异步线程、硬件与运行负载会影响即时快照和耗时，因此固定输入不能承诺逐毫秒完全相同；稳定后的候选单独检查，电脑耗时不作为平板性能结论。

只有用户明确要求设备诊断时才使用 `android-run`。本地算法测试通过也不等于输入法界面、按键触摸或实际上屏通过，这些仍须标为“未验收”。本批仅增加测试流程，未修改选词算法。

- Windows → Ubuntu-22.04-D 的默认入口实际跑通；309 个原生编译步骤完成，动态依赖及必要 JNI 导出正常。所有兼容调整在测试源码副本中，未构建 APK、未安装应用；用户要求停止使用平板后，没有再调用设备。
- 72 项相关 Python 检查通过；Java 主机入口另有 17 项参数和路径保护检查通过。自定义文本“你好，睡不着。银行在哪？”成功转换为 3 段、9 字、27 个数字按键的夹具。
- 原聊天实际本机回放 130 段、594 个汉字，两个过程共 4,370 个观测时点，输入和覆盖校验完整、无执行问题；语法与句子模型最终均为 `ready`。
- 正文 488 字的即时直出为 211/488（43.24%），逐字停顿后为 214/488（43.85%）；83 段正文末尾首选命中 44/83（53.01%），前百召回 62/83（74.70%）。33 个已审定异常时点全部重现，质量退出码为 1，排序问题仍未修复。

证据目录：`.codex-artifacts/t9-host-20261003/`。仅离线读取之前保存的 Android 证据作跨平台诊断，本次所有首选一致，但有 2 个观测的目标名次不同，525 个观测的完整候选列表不同，因此没有把两种平台设为同一回归基线；详情在 `saved-android-alignment.json`。输入法界面和实际上屏仍未验收。
