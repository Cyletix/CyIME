# 1.1.6 Debug：短编码、候选布局与公共基础联想

## 本轮修改

- 单键预编辑：7 的原生首选汉字是“是”；旧转换器却把其单键声母 s 扩成 sh。现在单键只显示一个字母；两键才可显示 zh/ch/sh。
- 九键拼写容错：旧 derive 规则把 sho(746) 当成 shou(7468)，导致“手”排首位。仅九键去掉该缺字容错；中文26键保持原规则。真实引擎回归：746 现在首选“亲/qin”。
- 顶部候选：按真实面板可用宽度、字形、注释测量完整前缀，不横向滚动、不露出半个尾词；超宽首词省略显示仍可选。
- 展开候选：从顶部实际显示前缀之后开始，保留全局引擎索引；单字筛选后仍使用原索引。联想后缀索引同步偏移。
- 中英文统一行高和字体内边距规则，并把实际文字基线锚到相同位置（回退字体的上升高度不同，仅统一容器高度不够）；展开页也统一行框。

## 公共语料接入方式

使用 LCCC-base 官方训练集按对话索引模34均匀抽样：200,604段对话、589,546句，生成9,191个上下文、29,245条续词关系。压缩资源160,873字节。训练脚本：`tools/ime_lab/build_base_associations.py`。

重建命令：

```powershell
python tools/ime_lab/build_base_associations.py D:/CyIME-Data/corpora/lccc-base/lccc_base_train.jsonl.gz app/src/main/assets/association/lccc-base-v1.bin
```

资源使用`.bin`封装gzip，避免Android构建自动解压并剥除`.gz`后缀导致读取失败。来源、MIT许可、训练数据/产物哈希随资源保存。

运行时：最多查找4次上下文后缀，不遍历整份公共语料；索引只读，独立于`user_ngram_cache.json`。公共权重上限0.25，个人学习和下载模型继续参与融合。启用智能联想后，未下载ONNX模型也可以使用基础联想；保留用户开关，不强制启用。

这一步是**已上屏文字后的续词联想**，不是输入中的拼音整句解码或全句重排，也不把公共语料当成用户本人历史。原“问题太”等组句问题仍未解决。

## 验证集质量边界
