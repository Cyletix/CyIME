# 2026-10-07 Android 首次附近配对确认修补

## 范围与结论边界

接手安全审查对接文档后，重新核对 `WindowsDevices.kt` 的当前源码：首次发现唯一附近设备会自动请求配对，收到格式正确的 HTTP 201 后直接调用 `confirmConnection()`，保存对方凭据并开启同步。发现广播与对方的成功响应不能证明用户已在自己的电脑上批准，这是首次建立信任的缺口。

利用前提是手机尚无已保存配对，且同网伪装服务能被发现并响应。审查及本轮测试不证明实际发生过入侵，也不证明 CyIME 导致此前恶意网页跳转；手机、平板实际安装内容尚未在本轮现场核对。已有固定证书的可信设备重连不是这个问题的绕过路径。

仅修改 Android 主目录 `D:/GitHub/CyIME`。Windows 代码、设备记录及系统防火墙由另一个对话处理，本轮未更改。

## 实现

- 附近发现仅展示电脑；首次配对由设置页点选电脑主动发起，不能由 mDNS 广播或后台发现直接触发。
- `WindowsNearbyPairing` 使用两分钟的尝试窗口。远端 201 只保留内存候选，不调用保存／启用同步；界面展示本机计算的连接码，明确要求对照自己电脑，用户点击确认才提交。
- 确认绑定当前请求 ID；取消、离开设置页、重新选择或切换扫码都会清除旧候选。迟到的旧响应和旧确认点击不能替换当前尝试。
- 超时覆盖远端等待和本机确认两个阶段，使用 Android `elapsedRealtime` 检查休眠后的真实经过时间，超时后不再发请求或接受确认。
- 二维码仍以用户扫描获得的证书指纹和密钥建立信任。响应的版本、服务 ID、设备 ID 和令牌格式校验原样移至 `WindowsPairingProtocol.received`，供两种入口共用。
- 已信任设备继续自动重连；发现只能更新其地址，不能替换原证书指纹或令牌。原 HTTPS 固定证书、禁用重定向、不经过代理及 AndroidKeyStore 包装存储保留。

## 验证与交付

26 项相关 JVM 测试通过，0 失败、0 错误：`WindowsNearbyPairingTest` 12 项、`WindowsPairingProtocolTest` 5 项、`WindowsPairingTlsTest` 3 项、`WindowsSecureTransportTest` 6 项。Android 界面测试编译通过。环境核对未发现 ADB 设备，因此界面测试未执行，也没有本轮手机／平板的实际渲染证据，不能宣称视觉或真机验收通过。

新增测试分为配对状态与真实本机 TLS 两层：前者检查远端 201、显式确认、取消、超时、休眠、迟到响应及错误数据；后者使用临时证书和本机 HTTPS 服务，检查陌生服务不能自动建立信任、已有凭据可连接、相同 ID 换证书不能收到令牌、重定向不能转移认证请求。仅使用假数据，不访问真实用户剪贴板。

另补 Android 界面测试：收到 201 前无确认按钮，收到后保留连接码与本机确认／取消操作，扫码入口在未配对和已配对状态均保留。编译与实际执行分别记录，不把编译通过当作渲染或用户验收。

| 关键条件 | 实际验证 |
| --- | --- |
