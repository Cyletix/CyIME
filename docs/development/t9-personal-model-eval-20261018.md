# 九键私人模型 p4 与完整 v3 对比（2026-10-18）

用户要求：私人模型要“全面超过”完整 v3 才能替换；之前 400 句个人留出集不够说明问题。本次只评估、不改代码、不改打包预设。

## 方法

- 引擎：「词库和词权问题」线程用 MSVC 编的 Windows 电脑端 `rime.dll`（当前安卓 jni 的 librime + CyIME 补丁 + `t9_ngram_model`）。复制到 `D:/CyIME-Data/tmp/t9-eval-20261018/probe/` 使用，原目录未写。两个数据目录除 `t9_ngram.lm` 外完全相同，均无用户词库（空学习状态）。
- 模型：v3 = `t9_ngram-model-v3-ls-tri.c3.lm`（212,706,156 字节，公开 Release 同款）；p4 = `private/t9_ngram-personal-p4.c3.lm`（215,007,628 字节）。
- 协议：每个用例按九键数字串一次打完，读前 10 个候选；看首选是否等于原文。**不含**逐键结果、停顿重排、librime-t9 的处理器与过滤器、上屏前文——这些要等电脑端回放引擎（WSL 缺 Java，待用户同意下载便携 JDK）。
- 用例（脚本 `D:/CyIME-Data/tmp/t9-eval-20261018/scripts/`）：
  - sms：公开测试集 `测试集-公开语料-20261018` 的 500 句 + 从同一 NUS 短信池按同一雾凇标注方法新抽 1500 句（固定种子 20261018，抽样先于任何运行），共 2000 句；两模型都没训练过。
  - lccc：公开测试集 500 句（v3 训练语料含 LCCC-base，仅参考）。
  - daily：CyIME 日常夹具 178 句。
  - personal：10-13 按会话 9:1 切出的个人留出集 400 句（只统计数字，Agent 未读句子）。
- 检验：逐题配对，两侧精确 McNemar。

前三名命中与首选几乎相同（例：sms 65.40 / 65.45），整串候选列表基本只给一条整句。

## 泄漏检查

- daily：178 句中有 74 句原样出现在个人训练语料里（测试句曾被贴进对话），p4 在 daily 上多对的 20 句**全部**在训练语料里。这组的提升是泄漏，不算数。
- personal：留出集 400 句里 22 句作为片段出现在训练语料中（无整行重复）；去掉后 378 句结论不变（+22/−3）。
- sms：2000 句里 25 句（多为“好的”“谢谢你”这类短句）作为片段出现在个人语料里；lccc 500 句里 8 句。

## 结论

- 通用说话（干净短信 2000 句）：p4 与 v3 打平，没有变差，也没有变好。
- 用户自己的说话风格（未见过的 378 句）：p4 明显更好，约 +5 个百分点。
- 所以 p4 不是“全面超过”，而是“通用持平、个人更好”。是否替换由用户决定；本次未改打包预设。
- 局限：只比整串首选；逐键、停顿重排和上文接续的完整回放还没跑；个人集偏技术话题、读音靠词典标注。
