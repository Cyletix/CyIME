# 语言、方案与布局选择界面

当前集成验证及交付状态见 [1.4.1 集成交付](integration-delivery-2026-10-03.md)；下文保留分支阶段记录。

分支 `codex/language-layout-selection`，基于 main `81fa341b`。仅修改源码及检查，未打包、未安装、未提交，界面未验收。

问题位于两个入口：设置中的语言管理已经有方案/布局选择，但键盘的 `SchemaListView` 仍直接展示后端组合卡片；布局下拉也曾把同布局的不同后端重复列入。

- 键盘入口改名“语言与布局”，依次选择语言、输入方案、键盘布局；同一组合有多个实际后端时单列“方案版本”。选择过程只修改面板草稿，点击“使用此组合”才调用原有服务切换流程；取消不写偏好。
- 设置页点开一个语言后使用同一套选择组件；开关单独控制启用，点语言标题不再误关语言。沿用原偏好写入接口，保存的组合用于下次切换语言。
- `InputProfileSelection` 按实际语言/方案筛选和去重布局，切布局不改变方案，切方案优先保留布局；再次选择同一方案或布局保留原后端版本。不存在的组合不生成 schema ID。
- 语言排序、组合排序及添加自定义布局保留在更多菜单；原排序键、旧偏好、方案资源、自定义布局文件均未迁移或重写。资源安装入口改名“输入资源”，与日常选择区分。

最终检查：应用及 AndroidTest Kotlin 编译通过；26 项 JVM 测试通过（InputProfile 12、InputProfilePreferences 1、InputModes 11、LanguagePreferences 2）。覆盖实际布局重绑定、语言隔离、旧配置读取、去重与版本保留、不可用组合拒绝；日志 `.codex-artifacts/language-check-final.log`。

设备用例已更新为独立选择及确认流程，含 280dp/2 倍字体、低高度与横屏下滚动到各字段、确认按钮可达、浏览不切换输入及版本选择；仅编译，未运行，不能宣称高度、裁切或交互区域已真机通过。用户已暂停 ADB 操作，因此未安装、未使用平板或手机验证；完整尺寸门禁未运行。
