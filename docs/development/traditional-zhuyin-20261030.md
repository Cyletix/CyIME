# 繁体输出与注音（大千），2026-10-30

台湾朋友提了两件事：简繁转换，以及注音输入。两个补丁按功能各一次提交：

1. 简繁转换：随包带 OpenCC 转换表（按台湾用字），设置 → 语言与方案 → 中文输出 → 繁体输出，默认关。
2. 注音（大千）：新方案 `cyime_zhuyin` 和注音键盘，默认不启用，在「已安装的方案」里打开。

两次都在云端会话里做，Kotlin 没有编译（云端没有 Android SDK），没有渲染截图，没有上真机。引擎部分用主机同源引擎回放检查过。

## 注音怎么做的

- 词库沿用雾凇（`dictionary: rime_ice`），拼写运算把拼音音节改写成注音、再落到大千键位，写法同 rime-bopomofo。雾凇没有声调，五个声调都认，可以不打声调，也可以只打声母（ㄋㄏ → 你好）。
- 候选一律经 `cyime_s2tw` 转成台湾正体，开关名 `zh_tw`，默认繁；不跟 26 键的「繁体输出」设置走。
- `cyime_tw.dict.yaml`：雾凇缺的台湾词和台湾读音（垃圾 ㄌㄜˋㄙㄜˋ、說服 ㄕㄨㄟˋㄈㄨˊ、健保、立委），1317 条，`tools/zhuyin/build_cyime_tw.py` 从小麦注音数据生成，权重按两边都有的词拟合到雾凇的尺度。
- `lua/cyime_zhuyin_tone.lua`：打了声调的音节，字读不出这个声调的候选排到后面（稅負 的 負 没有 ˊ，排在 說服 后面）。只重排前 100 个。
- 键盘：xime.yaml 的 `keyboard.zhuyin`，11/10/10/10 四行，下面三行缩进半键，删除键在第四行末尾，底排同 26 键。键帽送注音符号，`ImeKeyRouter.routeZhuyinKey` 按 `ZhuyinKeys` 换成大千键码给 Rime。
- 空格跟在音节后面是第一声；已经有声调时空格选词。没打字时按声调键照原样上屏这个符号，连按两个声调第二个不收。回车上屏屏上的注音（不是键码）。
- 大千里数字和 `, . - / ;` 也是注音键：屏幕上别处送来的这些 ASCII 符号照符号上屏，不当拼写；底排逗号键直接上屏全角「，」。
- 注音不挂个人短语（短语是拼音字母码，在大千里是另一串注音），不给中文联想（联想表只有简体）。

## 未验收

- Kotlin 未编译、单测未跑，键盘未渲染、未上真机：键盘外观（11 列、半键缩进、删除键位置、底排）、点按、上滑数字、空格当第一声、回车、删除都要在设备上看。
- 回放用户目录没有九键整句模型，`t9:` 整句重排在注音里的效果没验。
- 实体键盘：字母键照大千键位能打；数字键（ㄅㄉˇˋㄓˊ˙ㄚㄞㄢ）被实体键盘的数字选词、数字直出先拦下，组字中的 `, . / ;`（ㄝㄡㄥㄤ）被「打拼音时的标点原样上屏」先拦下。实体键盘注音只部分可用，要另做。
- 工具面板（剪贴板搜索等）里打注音，注音符号原样写进面板，不组字。
- 语音模式的占位键盘第三行仍是 26 键的样子（Shift、删除占位）。
- 繁体输出（补丁 1）：26 键、九键、14 键里繁简转换排在候选规则后面，开着繁体时长按删掉的候选按繁体字记，不会一直藏住；注音方案把转换排在前面，没有这个问题。
