# 语言、方案、布局与引擎配置

日期：2026-10-01。本轮只改源码并做针对性检查，不打包、不安装、不发布。

## 定义

| 概念 | 职责 | 示例 |
|---|---|---|
| `InputLanguage` | 自然语言，约束语言资源与识别模型 | 中文、英文、日语 |
| `InputScheme` | 输入序列的编码与解码规则 | 拼音、双拼、五笔、罗马字、假名、直接输入 |
| `InputLayout` | 按键位置、形状及交互排列 | 26键、九键、14键、自定义合并布局、手写板 |
| `InputMode` | 获取输入的方式 | 键盘、手写、语音 |
| `EngineProfile` | 实现上述组合的引擎配置 | Rime `rime_ice`、`t9_pinyin`；直接输入；手写引擎 |

`UNSPECIFIED` 是导入配置缺少语言信息的标记，不是第四种自然语言。保留这类配置的入口，不默认归为中文，也不由名称前缀猜测语言。

## 本轮实现

集中模型在 `settings/InputProfile.kt`。以下组合属于同一拼音方案，不是三个不同方案：

| 语言 | 方案 | 布局 | 内置引擎配置 |
|---|---|---|---|
| 中文 | 拼音 | 26键 | `rime_ice`；旧配置 `pinyin_simp` 继续保留 |
| 中文 | 拼音 | 九键 | `t9_pinyin` |
| 中文 | 拼音 | 14键 | `pinyin_14jian` |
| 中文 | 双拼 | 26键 | `double_pinyin_flypy` |
| 中文 | 五笔 | 26键 | `wubi86` 等版本 |
| 日语 | 罗马字 | 26键 | `japanese`；兼容 `jaroomaji` |
| 日语 | 假名 | 假名九键 | `japanese_kana` |
| 英文 | 直接输入 | 26键 | 产品入口为 Direct，现有引擎适配仍使用 ASCII 状态 |

`describe` 描述内置/已安装后端的语义和默认布局；`current` 使用实际的 `xime.yaml` / `xime.custom.yaml` 布局绑定，未绑定仍遵从原有全键盘规则。配置尚未读取时，设置页可以展示目录默认值；读取后，设置摘要与键盘路由使用实际绑定。自定义按键的改位、合并、名称不改变其拼音方案身份。

`InputUIState.inputProfile` 和 `KeyboardUiState.inputProfile` 由现有实际引擎状态投影，不再额外保存一套可能漂移的 language/scheme/layout 三个字段。ASCII 投影为英文直接输入，不被底层暂存的中文/日语 schema 误导。

已接入：语言分组与切换摘要、语言设置的方案/布局选择、T9/笔画/手写布局路由、分体适用范围、假名键盘与日语按键/回车/标点路径、拼音编辑能力及 14 键语义判定。内置描述缓存复用；按键路径不读取文件。

语言设置只提供已启用的实际组合，先选方案、再选布局；没有相应引擎配置的组合不会凭空生成。同一布局有多个后端版本时保留版本名称供选择。设置保存的是该语言下次被选中时使用的组合，不在浏览设置时直接向当前编辑器切换引擎。

`selected_input_profile_<language>` 保存明确选择；没有新值时读取原来的 `last_input_mode_<language>`。普通会话保存只更新后者，不能覆盖设置页刚选的新组合。键盘明确选择组合成功后更新前者。旧 schema ID、排序键、词库及自定义布局文件不重写、不删除。

## 导入配置

可以在已有 `schema:` 块中显式声明：

```yaml
schema:
  schema_id: my_romaji
  name: 我的日语配置
  language: ja
  input_scheme: romaji
```

`language` 使用 `zh` / `ja` / `en`；`input_scheme` 对应 `InputScheme.id`。声明必须符合后端的实际编码规则；例如 `romaji` 接入当前罗马字大小写与假名转换协议。布局仍由 `keyboard.<section>.schemas` 绑定，不放进 language 或 scheme 字段。完整发现后发布不可变描述表，删除声明后重新发现会清除旧含义；查询过程不做文件 IO。

## 手写边界

`profile.handwriting()` 保留键盘语言与返回键盘时的方案，改为手写输入方式和画板布局。当前安装的分类器使用中文字表，识别能力仍只有中文。2026-10-03 按用户要求，中／英文键盘均可明确打开中文手写：`HandwritingLanguages.recognitionLanguageForKeyboard` 为这两个入口选择中文识别，英文画板标注“中文手写”，退出后恢复原键盘；日语和未标注语言仍提示不支持。`handwriting` 旧 schema 别名仅为已有配置的兼容入口，不能用于新增语言枚举。

主画板、手写查词将明确选择的识别语言传入 `HandwritingEngine`，引擎仍拒绝英文／日语识别请求，没有扩大底层模型能力。候选、笔画任务和待提交队列跟随原键盘语言及输入会话失效；查词清屏同时取消旧任务并重建识别缓存。自定义布局即使把日语方案绑定到手写板，也只展示提示与“选择输入方案”入口；手写查词保留“返回键盘”。英文入口、返回原布局与低高度提示页的界面用例已编译，尚未运行验收。

## 语音按语言选择（2026-10-02）

录音入口从 `InputProfile.language` 取得本次语言，经过录音工作线程和本地服务传给模型。能力表集中在 `speech/SpeechLanguages.kt`，不根据 Rime schema 名称猜测。

| 当前语言 | 现有模型能力与选择 |
|---|---|
| 中文 | 保留兼容的用户选择，包括原有双模型校正 |
| 英文 | Paraformer 或 SenseVoice；原选择兼容时优先保留 |
| 日语 | SenseVoice |
| 未标注语言 | 明确提示，拒绝开始识别 |

能力来自当前模型目录；SenseVoice 的中英日能力可核对 [Sherpa-ONNX 官方模型说明](https://k2-fsa.github.io/sherpa/onnx/sense-voice/pretrained.html)。产品当前只开放领域模型已有的中英日，不因上游支持其他语言就自动新增产品语言。

选择规则：兼容的用户选择缺资源时提示补齐，不擅自换模型；原选择不兼容当前语言时，只在已安装且支持该语言的模型中为本次录音选择替代。双模型方案的主识别器不兼容时，优先单独使用已安装的 SenseVoice 校正模型。没有适用模型则提示下载，录音过程不自动下载，也不覆盖用户保存的原选择。SenseVoice 使用本次语言参数；模型缓存键包含语言，避免重用另一种语言的配置。

2026-10-03 按用户要求区分键盘编辑语言与本次录音语言：开始录音时固定识别语言，当前非英语语言与英语键盘来回切换保留会话、预启动和识别结果，归一化也继续使用起始识别语言。`VoiceKeyboardLanguages` 同时记录产品语言与底层键盘语言，切到另一种非英语语言或切换输入框才取消旧录音及迟到回调；ASCII 状态下更换底层语言也会失效。只切同语言布局不取消。停止后等待最终结果期间，单纯语言键不当作手动文字修改；真正改字仍丢弃待返回结果，避免覆盖用户编辑。新录音仍等待旧录音线程收尾，中文口述标点转换仅在本次录音语言为中文时启用。

在线插件协议尚无语言能力声明和语言参数，本轮保留中文兼容入口；英文、日语明确提示使用本地多语言模型。没有把未核实的插件能力默认视为多语言支持。

### SenseVoice 静音误识别（2026-10-02）

用户确认“Yeah”出现在没说话、停顿或结束录音时。本次确认了一条会把全静音交给识别器的代码路径：SenseVoice 单模型/二次校正按 6 秒目标、额外 2 秒余量强制分段后，`continuation` 曾无条件开启下一段，绕过 VAD 与能量判断。即使接下来全是静音，也会提交一段新的识别任务。回归测试在修复前复现了多余的静音任务；假识别器用“Yeah”标记该任务，不应将此写成已用原生模型重现用户录音。

现已移除强制续段。VAD 保持历史状态，连续语音仍可接续，下一段则必须满足现有人声与能量条件。SenseVoice 返回的 `lang=nospeech`（含 `<|nospeech|>`）在文字清理前变为空结果；Sherpa 将元数据与正文分开返回，先前只读取正文会丢掉这个信号。修复覆盖单模型和二次校正，不屏蔽“Yeah”“嗯”“はい”等真实短词，也不因背景音乐/咳嗽事件标签单独删除可能同时存在的语音。

依据：[Sherpa 1.13.8 结果字段](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.8/sherpa-onnx/kotlin-api/OfflineRecognizer.kt)、[SenseVoice 标签解析](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.8/sherpa-onnx/csrc/offline-recognizer-sense-voice-impl.h)、[官方无语音标签](https://github.com/modelscope/FunASR/blob/main/funasr/utils/postprocess_utils.py)。当前 Kotlin 结果没有识别置信度字段；项目 `SpeechResult.confidence` 的默认值不能当作本地模型实际置信度。

本次不盲目提高检测门槛：Silero VAD 仍配置为 0.6、最短人声 150ms，保留预缓冲以免丢掉轻声开头。若实录中仍有噪声被判成人声，需要对安静、风扇/敲击/呼吸、短词与轻声、长句后停顿分别统计误触发和漏字，再调整检测参数。原生模型对噪声的实际效果尚未验收。平板虽已连接，但另一会话正在同机测 T9 延迟并覆盖安装，本次只执行电脑上的回归与编译，不切换输入法、不安装或运行设备测试。

- `ScelDictionary` 在后台解析常见 0x44/0x45 格式，保留分音节拼音、同音异词，去除单库内重复词码，拒绝网页、截断文件、非法拼音引用和控制字符。限制单文件 16 MB、25 万记录。不将不明含义的 SCEL 扩展字段当作可比较词频；补充词条统一使用 Rime 权重 100，实际候选排序还需真机评估。
- `CellDictionaryStore` 将转换文件、来源、原文件 SHA-256、已选/已应用两组状态保存于私有 `files/cell-dictionaries`。文件原子替换；下载与转换失败不动已有词库。本次下载语料仅放在本地 `.codex-artifacts/sogou-validation`，不随 APK 或仓库分发。
- `CellDictionaryRime` 以 `InputProfile` 的中文、拼音/双拼及 Rime 键盘能力判断适用范围，不按 schema 前缀判断业务。日语、英文、手写、五笔及未知编码不注入中文拼音词。主词典名称仅在此部署适配层读取；不同主词典不能共用音节编号，所以分别生成 `user_cyime_cells_<hash>.dict.yaml`，同一主词典的已选集合只形成一个附加查询表。
- 通过标记块追加 `translator/packs/+`，保留原 packs、自定义短语、布局、学习和其他自定义设置。幂等更新不改变未变文件时间。对已有同名追加补丁、流式 `patch` 等不能无损合并的写法明确报错，不重写第三方 YAML。所有补丁先完成解析检查再落盘。
