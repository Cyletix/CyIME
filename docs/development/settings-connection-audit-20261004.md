| 用户目标 | 实际问题 | 本轮修正 |
| --- | --- | --- |

| 同设备截图复制后提示粘贴 | 异步读取前已记录“提示过”；隐藏键盘时连从未显示的图片也被消耗，读取失败又被时间戳去重挡住；混合 ClipData 可能取错 URI | 区分待读取、真正呈现和关闭，失败允许再次读取；检查所有 URI / Intent.data 与实际 MIME，真正显示后关闭才持久化去重 |
| 不填写地址、能发现电脑 | Windows 为随机虚构主机名广播 SRV，却未提供可解析的地址；仅补 IPv4 参数仍不能解析；虚拟／IPv6 网卡枚举可抛异常或抢占地址 | 逐网卡容错、选择实际可达局域网接口；使用系统真实 `.local` 主机名及对应 IPv4/接口。平板 NSD 已实际解析成功 |

| 同步页面能理解，开关对应真实状态 | 原生连接与旧插件表单混在一起；切到原生服务时可能用旧插件回填或显示错误开关状态 | 默认附近电脑／已连接电脑；旧服务收在高级区域；页面观察实际服务 ID 与启停状态；只读状态探测不读取剪贴板 |
| 输入方式只是选择器 | 布局与方案用大容器，选中和未选中尺度不一致 | 当前组合、同规格横向布局选项、方案选项、明确的管理入口；组合仍验证真实兼容关系，不拼造 schema |

## 实际验证与证据

证据位于本机 `.codex-artifacts`，包含失败结果，不仅保留成功日志：

1. `settings-repair-jvm-final.log`：1509 项测试，0 失败／错误／跳过；涵盖图片提示状态、图片来源选择、协议解析和 QR 解码。QR 使用实际生成的旧／新二维码，在多尺寸和旋转下解码；不等同摄像头真机扫码。
2. `candidate-comment-probe/result.log`：第一次真实引擎检查失败，证明只改翻译器选项仍不够；据此找到 Lua 清空注释。
3. `candidate-comment-probe/result-fixed.log`：rime_ice、14 键拼音、小鹤双拼、小鹤双拼 14 键和五笔 86 均返回非空真实注释；分别覆盖拼音与编码，不评判这些输入的整句排序。测试使用隔离词库与生产 JNI，不改个人词库；源程序保存在 `tools/ime_lab/host_replay/CandidateCommentProbe.java`。夹具有可选个人词库缺失和 OpenCC 警告，不作为这些路径通过的证据。
4. `candidate-comment-resources.log`：准备词库任务成功，产出的 `corrector.lua` 保留宿主要求的注释；资源声明同步记录修改来源。两个 librime 补丁均能对工作源码反向校验。
5. `settings-wiring-audit.json`：124 个偏好方法的定义／调用点清单。没有调用的 16 个方法包含私有辅助、旧布局／旧振动等接口；这份清单用于定位遗漏，不等同 124 项行为测试，也不覆盖所有独立偏好类、插件和第三方应用行为。
6. `nsd-tablet-tls-final.log`：SM-X800 使用实际 Android NsdManager 发现并解析 Windows 服务，连接局域网地址，校对发现指纹和 TLS 叶证书，未带令牌访问 `/api/status` 得到 401；没有自动同意首次配对，也没有读取用户剪贴板。Windows 安装位置、备份、哈希和自检见对端 `docs/CLIPBOARD_PAIRING.md`。

第一次回放构建因补丁上下文过期失败，修正两个规范补丁后才完成运行。没有将工作子模块中其他生成改动吸进补丁。`.patch` 中新增的空白上下文行会被父仓库 `git diff --check` 报空格；实际源码／文档的空白检查单独执行，不能把补丁警告写成“全量检查通过”。
