# 固定 iOS 背景与尺寸调节透明度恢复

用户要求恢复原 iOS 固定背景主题，透明度保持独立；尺寸/悬浮调节只提供直接透明度滑条，调整时隐藏其余元素，不进入二级菜单。本轮按兼容修复使用 1.9.12 / 20261104，保留既有日语「つ→っ→づ→つ」和其他未提交改动。

## 实现依据与范围

- 原主题取自 Git `1044aef6` 的 `TransparentGlassTheme.create`，最初加入于 `785c9728`：135°渐变，原色`#9CACCC → #D6BCC9 → #85BFBF`。进一步核对同版本 `FrostedGlassBackground`，原背景还叠加浅色20%白、深色80%黑的默认遮罩；只恢复原色会使深色主题底图过亮。因此把原默认可见背景烘焙为浅色`#B0BDD6/#DEC9D4/#9DCCCC`、深色`#1F2229/#2B2628/#1B2626`，其透明程度不再绑定实时透明参数。键帽及文字继承完整黑白调色板。目录项名称为「iOS 渐变」，沿用 `transparent_glass` ID 保留选择及用户颜色覆盖；不将旧 ID 代理到黑白，不在读取主题时自动开启玻璃。
- 配色、背景/按键不透明度、模糊继续由独立设置保存。用户后续六张图明确黑白变化指背后应用；既有深浅参数交换规则保留。
- 尺寸调节恢复原 `keyboardOpacity` 单滑条（透明度0–70%，整体alpha 1–0.3），去掉玻璃二级编辑及其草稿联动。点标签或直接拖动在原位置进入编辑状态，隐藏遮罩、尺寸边框、移动/留白手柄、重置及模式按钮；保留滑条、返回、完成。返回保留本次草稿，退出整个调节取消，完成沿用原事务保存。玻璃开启也允许整体alpha生效。

## 可读性问题的实际边界

当前浅色默认背景不透明度20%、按键80%；深色相反。键帽叠加后宿主影响为16%，但无键帽的候选栏在浅色下仍暴露80%宿主。按现有sRGB叠色计算，浅色黑白主题在纯黑宿主上候选底约`#303030`、文字`#454545`，对比度约1.37:1；纯白宿主约9.38:1。蓝、紫浅色在黑宿主分别约2.16:1、1.97:1。均匀底色不会因模糊获得更高对比；文字描边不解决整体底色问题。

这是源码公式计算，非本轮新真机证据。此前仅测空格键可读性的检查不能代表候选栏。固定渐变在关闭真实透底时可提供固定背景；如果开启真实玻璃且降低背景不透明度，仍会混入宿主，不能宣称任意参数和宿主下通用可读。没有暗中提高用户alpha或关闭玻璃。设置文案去掉“保持清晰”的无条件承诺，改为准确描述背景/键帽参数不淡化文字图标。
