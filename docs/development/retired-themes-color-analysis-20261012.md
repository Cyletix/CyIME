# 停用配色的问题分析与重建方案（2026-10-12，未验收）

停用的配色有 21 套：`xime.yaml` 里 1.9.15 时移除的 20 套，加上 10-11 从列表隐藏的“跟随系统动态配色”。动态配色是按“只留四个主题”隐藏的，本身没有查出配色问题。

数据来源：`tools/theme_audit.py`（复现键盘取色逻辑）跑 HEAD 版 `xime.yaml`。对照图和重建脚本在 `.codex-artifacts/theme-analysis-20261012/`。

## 四类问题

| 类别 | 主题 | 现象 | 原因（配色理论） |
| --- | --- | --- | --- |
| 纯色主题深色 | 海洋蔚蓝、落日橙光、沉稳石墨、浪漫玫瑰、青碧如水 | 字/键 3.9–4.5:1，键/底 3.4–3.5:1：按键是一片发灰的亮块，字发虚 | 只给了背景色和强调色，深色键帽用的是全局默认的半透明白。白叠在高饱和深底上，得到中明度、低饱和的灰。① 明度：键比底亮太多，比字暗太多，层次全挤在中间。② 色相：中性灰贴在饱和蓝/红底上，同时对比让灰显得“脏”。 |
| 渐变主题深色 | 极光、落日余晖、深海、紫梦、玫瑰、森林 | 同上，字/键 3.8–4.3:1 | 深色键帽是 `0x5AFFFFFF`（35% 白），问题同上。 |
| 浅色系（pastel） | 樱花粉黛、晴空浅蓝、薄荷浅绿、丁香浅紫、蜜桃浅橙、奶油米白 | 键/底只有 1.06–1.09:1，按键浮不出来；没有深色版，深色模式下仍是一整块亮粉/亮蓝 | ① 键色和底色明度几乎相同（相差约 1–2 个 L*），低于能分辨的约 1.15:1。② `color_dark` 直接复用浅色值，深色模式完全没有设计。③ 字色是中明度的去饱和色，只有 6.6–7.7:1，比其他主题弱一截。 |
| 图片主题 | 夜幕之影、暮色之桥、大漠流金 | 大漠流金浅色字/键 3.6:1，功能键 2.9:1 | 蓝字（约 220°）放在金黄沙漠（约 60°）上是补色并置：明度接近时边缘会“振动”，难读。半透明键帽的可读性完全取决于图片局部的明暗。 |

另外，所有纯色主题的浅色版背景都是同一个中性灰 `#E3E4E8`，只有回车键颜色不同，主题之间几乎没有区别。

## 重建方法：单色相 + 固定色调阶梯（OKLCH）

每个主题只取一个色相（主色），表面（底、字母键、功能键）都用这个色相、低彩度，各角色的明度固定：

| 角色 | 浅色 L / C | 深色 L / C |
| --- | --- | --- |
| 背景 | 0.945 / 0.022 | 0.165 / 0.025 |
| 字母键 | 0.995 / 0.006 | 0.315 / 0.022 |
| 功能键 | 0.875 / 0.035 | 0.245 / 0.028 |
| 文字 | 0.24 / 0.035 | 0.955 / 0.010 |
| 强调（回车） | 主色，L 夹到 0.52–0.62 | 0.80 |

主色本身接近灰时（如石墨），表面彩度按主色彩度等比降低，保持中性。

结果（全部 20 套，浅色/深色）：

- 字/键：浅色 16.1–16.4:1，深色 11.3–11.4:1（原深色最低 3.8）。
- 功能键文字 11.3 / 14.2:1 以上。
- 键/底：浅色 1.15–1.17，深色 1.48–1.50（原浅色系 1.06，原深色 3.5）。
- 功能键与字母键可区分：浅色 1.42–1.46，深色 1.26。

做法上：键与底同色相，靠明度分层，不靠换色；彩度只放在强调色上，表面保持安静。这样每套主题仍有自己的色调，但不会出现灰键压在饱和底上的脏感。

## 代价与待定

- 重建后各主题表面彩度都很低，差别主要在底色的色调和回车键颜色，比原来更素。
- 渐变和图片主题若要保留特色，可以保留渐变/图片作为背景，但需要按上表把明度映射到背景档，图片加同色相遮罩，键帽改为不透明的同色相色，而不是半透明白。
- 玻璃模式下的表现还没有用新色值实测。
