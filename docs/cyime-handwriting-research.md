# 中文手写调查与后续方案（2026-09-24）

本轮能确认并修复的是候选范围和低置信度拆分；还没有能证明全面提高汉字准确率的新模型。ResNet 是可用的架构，但不是下载一个网络结构就能替换当前模型的完整方案。

## 当前模型和工程问题

当前市场 ochwpro v1.0 为笔画序列 Transformer 单字分类器。上游 README 报告 CASIA 测试集 Top-1 为 90.46%；这不是手机实写验收值，也不能直接和不同数据集的其他论文数字比较。[上游仓库](https://github.com/ximeiorg/ochwpro)

核对了上游提交 `54c326d33d86cc0754dbea5a36c1448682c8202c` 的 dataset.py、demo.py、export_onnx.py：200 点固定输入、每笔最多 8 点、五维坐标/差分/抬笔特征与 Android 基本一致。因此没有凭猜测改成图片输入或改变归一化。上游演示会优先筛选汉字，Android 之前直接把混合字符候选送给切分器，遗漏了这层约束。[演示实现](https://github.com/ximeiorg/ochwpro/blob/54c326d33d86cc0754dbea5a36c1448682c8202c/ochwpro/demo.py) · [训练特征](https://github.com/ximeiorg/ochwpro/blob/54c326d33d86cc0754dbea5a36c1448682c8202c/ochwpro/dataset.py)

0.1.6 的处理：

- 中文手写从更多原始候选中选择汉字，不用标点、字母和特殊符号补满列表；保留原概率，避免把低分候选重新归一化成虚假的高置信度。罕见汉字、繁体字仍保留；数字和标点使用已有数字/符号键。
- 无明显换字停顿、笔画仍在单字范围时，如果多段候选缺乏把握，则保留完整笔迹的候选，不因为分成几段平均分略高就把一个字拆成多个。明确停顿或各段高置信度的多字输入仍保留。
- 修正 native 库已经加载后，模型初始化返回失败却被 Java 标成成功的问题。

## 实际模型对照

在独立 Android 模拟器安装市场相同文件并校验 SHA-256：

- ochwpro.onnx：`eb04d62a314c7d7bac4e34d6ce0c24137474d30ff94b929115a621385420ce13`
- char_index.json：`171cf2ac23731428ac9dd28f64be82dece5f66a0ca3d674ffb3b567b51532176`

以下是固定合成笔画的诊断，不代表用户字迹、准确率基准或真机性能。测试源码 `HandwritingCandidateAuditTest.kt` 可复现，原始报告在本地 `.gradle/cyime-016/handwriting-{before,final}.json`。

| 预期 | 修改前最终候选 | 修改后最终候选 | 结论 |
| --- | --- | --- | --- |
| 一 | - | 一 | 非汉字符号不再压住汉字 |
| 中 | ▽ | 也 | 符号消失且不再拆成“一井”，但识字仍错误 |
| 大 | 大 | 大 | 保持 |
| 木 | 木 | 木 | 保持 |

“中”的失败说明过滤候选解决不了模型能力；合法汉字部件如“丨”“丶”也不能全部当符号删除。需要真实单字、连写和叠写样本进一步评估，而不是继续堆启发式规则。

## 可选方案

| 方案 | 能解决什么 | 需要补齐什么 |
| --- | --- | --- |
| Google ML Kit Digital Ink | 直接接受触屏笔画；官方说明与 Gboard 手写使用同类技术，模型下载后在本地识别，支持中文 | 优先作为效果对照；验证模型下载和目标设备兼容性、单字及多字体验、长尾延迟。SDK/模型适用 Google 条款，不能当作可自由打包的开源 ONNX 权重 |
| 中文单字 ResNet/CNN | 把笔迹渲染成图后做汉字分类，方案成熟，可以端侧推理 | 需要实际中文权重、字符表、匹配的图像预处理、可分发许可和手机笔迹测试；单字网络本身不解决连续多字分段 |
| 继续训练 ochwpro／换序列模型 | 可直接保留现有笔画采集与本地 ONNX 管线 | 收集失败笔迹，按书写者隔离训练/验证，补足触屏数据；多字场景评估序列解码和语言约束，不能只依赖单字切分分数 |

Google 的 [Digital Ink 介绍](https://developers.googleblog.com/digital-ink-recognition-in-ml-kit/) 和 [Android 接入文档](https://developers.google.com/ml-kit/vision/digital-ink-recognition/android) 说明了本地处理、语言模型下载、书写区域及前文上下文。它适合用来建立对照，但本轮没有集成、下载其模型，也没有声称已达到 Gboard 的准确率。[SDK 条款与数据说明](https://developers.google.com/ml-kit/terms) 还说明会收集使用/性能指标；接入前需核查本项目的分发方式和对应告知。

CNN 在中文手写中有良好研究结果，例如 [Yang 等人的在线中文手写研究](https://arxiv.org/abs/1505.07675) 将方向等笔迹特征与卷积网络结合。这个结果支持“卷积网络可以做好”，不能证明“任意 ResNet 一定比当前 Transformer 好”。两者必须用同一组实际字迹和同一字符集比较。

建议后续验收：至少覆盖常用单字、复杂字、连写、叠写、慢写补笔和撤销；记录首选/前五命中、错误拆字数、额外符号数、首个候选和定稿的 p50/p95 延迟，以及低端设备峰值内存。现有采集模块可以记录经用户同意的本地笔迹，避免仅用四个合成样例选模型。词库继续作为独立质量问题处理，本轮未改中文词库。
