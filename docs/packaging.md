## 版本如何确定

2026-10-03 先以 20261042 交付前序修正，20261043 交付默认比例，20261044 修正手动调节硬限制，20261045 加强远处阻力并沿拖动路径渐变计算；四份均已实际安装、核对版本与文件。46、47 又用于整合验证及候选偏移修正，48 为玻璃主题归属调整后的最终正式交付；42～48 均已占用，本轮正式发布使用 20261049，下一份不同源码交付至少使用 20261050，不按日期重算。

2026-10-02 的 20261040 安装平板后发现顔文字被全角转换，修正后以 **20261041** 再次覆盖安装并核对签名、架构、版本及实际安装文件。两份固定产物均保留，20261040、20261041 已占用，后续不同源码交付需继续递增，不能覆盖同号文件；详情见 [本轮界面整理](development/clipboard-expression-refresh.md)。

版本号由 Agent 负责判断，用户只需决定交付时机。以最后一个已发布正式版为基线，检查本次实际交付的累计改动，按最高影响确定一次；多个对话、提交或功能共用一个发布批次，不各自加一次版本。已确定的未发布目标继续沿用，除非实际交付范围改变了版本级别。

| 本次交付内容 | 编号规则 | 例子 |
|---|---|---|
| 兼容的问题修复、性能改善、现有交互打磨 | PATCH 加一 | 1.4.0 → 1.4.1 |
| 增加兼容的新功能，或形成一批明显的能力改进 | MINOR 加一，PATCH 归零 | 1.3.20 → 1.4.0 |
| 引入不兼容的用户配置、数据或插件契约变更 | MAJOR 加一，其余归零 | 1.4.3 → 2.0.0 |

本轮包含首次初始化按设备配置选模、九键候选切换等新增能力，因此目标为 **1.4.0**。如果从 1.3.20 单独交付只含修复的维护包，才会选 1.3.21。大量内部重构不自动意味着 2.0；有兼容迁移且用户原有配置和插件仍可继续使用时，按实际功能影响判断。

规则借鉴 [语义化版本](https://semver.org/lang/zh-CN/) 并应用于输入法的功能和兼容契约；升 MINOR 时归零 PATCH。废止“每次本地修改加末位、正式发包一律加中间位且保留末位”的旧规则。历史发布说明保留原记录，不作为当前规则。

日常编辑、测试和失败重试不改显示版本号。正式发布后不覆盖同号软件内容；后续修复使用新的 PATCH，不再只给 Release 标签加 `-r2` 而让应用显示相同版本。发布前由 Agent 核对远端正式版本、标签及实际源码范围，避免只根据本地旧标签判断。

Android 用独立的 `versionCode` 判断升级顺序，与显示用的 `versionName` 分开；后续交付序号必须增大，见 [Android 版本管理](https://developer.android.com/studio/publish/versioning)。本批初始预留 20261035，从原源码 20261034 递增而来，不是日期；实际覆盖交付已顺次使用至 20261041。同批普通版与内置版共用版本名和序号；交付前核对所有已有交付记录，若另一对话已使用该序号交付不同源码，则再次递增。不得把每天编辑或同批双版本构建计作两个产品版本，也不得用当天日期覆盖计数器。

## 打包与安装时机

遵循用户于 2026-10-01 调整的流程：**开发完成后不自动生成 Debug/Release APK、不自动 ADB 安装、不自动发布。** 等用户明确指定对应动作；继续做相关编译和针对性验证，未经真机验证标明“未验收”。正常覆盖安装保留数据，不卸载、不清数据。

以下仅列入口，不代表立即执行。尺寸打包门禁目前暂停；`build-apk.ps1` 默认只构建请求类型，只有显式 `-RunLayoutGate` 才追加完整设备门禁。未运行时回执写 `layoutGate: not-run`，不能写通过。发布脚本同样接受明确记录的 `not-run`，不读取旧门禁报告冒充本次通过；仍核对源码、版本、双包类型与文件哈希。本轮重装已由用户单独明确授权，不改变今后不自动打包／安装的规则。

```powershell
# 正式包（默认）
./scripts/build-apk.ps1
# 调试包，文件名带 -debug，避免误认为正式包
./scripts/build-apk.ps1 -BuildType Debug
```

脚本会把当前构建类型的旧包、另一类型的旧版本包移入
`app/build/outputs/apk/archive/<时间>/<类型>/`，不会删除历史包，也不运行 clean。
构建失败会报错，不会把旧包当成新包。成功后打印实际绝对路径，并生成 `latest.json`（版本、类型、路径、SHA256）。
若构建器将 APK 保存在 `intermediates/apk`，脚本读取其生成的定位文件，限定路径在本次构建目录内，校验应用身份和版本后再复制到交付目录；不猜测或挑选历史安装包。
正式包在 `app/build/outputs/apk/release/`，调试包在 `app/build/outputs/apk/debug/`。
直接执行 Gradle 不会归档旧包，本地发包统一使用上述脚本。

```powershell
# 安装当前 Debug 包（自动识别版本、设备架构和完整文件名）
./scripts/install-debug.ps1
# 正式包安装
./scripts/install-release.ps1
```

安装脚本只选择当前源码版本的对应类型安装包，自动识别设备架构，拒绝旧包或多设备歧义。
有 `app/keystore.properties` 时，Debug 与 Release 沿用同一发布签名与应用 ID。
没有正式密钥的 Debug 是开发构建，不能覆盖正式版；不可通过卸载绕过签名冲突。
`-Action uninstall` 是显式卸载，会删除应用数据，正常更新不要使用。
