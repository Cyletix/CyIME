2026-10-03 先以 20261042 交付前序修正，20261043 交付默认比例，20261044 修正手动调节硬限制，20261045 加强远处阻力并沿拖动路径渐变计算；四份均已实际安装、核对版本与文件。46、47 又用于整合验证及候选偏移修正，48 为玻璃主题归属调整后的最终正式交付；42～48 均已占用，本轮正式发布使用 20261049，下一份不同源码交付至少使用 20261050，不按日期重算。

版本号由 Agent 负责判断，每轮应用修改默认打包安装，用户决定公开发布时机。以最后一次实际交付为基线，检查本轮累计改动，按最高影响确定一次；连续补充、多个文件、编译和安装失败重试共用一轮目标，不各自升号。交付完成后下一轮修复必须递增 PATCH，不以 GitHub 是否公开发布为边界。1.8.1、1.8.2、1.8.3、1.8.4、1.8.5 都是正常修复交付，补丁位可以超过9。固定入口读取已经验证的安装回执，阻止只提高 versionCode 却沿用已交付版本名。

| 本次交付内容 | 编号规则 | 例子 |
|---|---|---|
| 兼容的问题修复、性能改善、现有交互打磨 | PATCH 加一 | 1.4.0 → 1.4.1 |
| 增加兼容的新功能，本次交付确实新增用户可用能力 | MINOR 加一，PATCH 归零 | 1.3.20 → 1.4.0 |
| 引入不兼容的用户配置、数据或插件契约变更 | MAJOR 加一，其余归零 | 1.4.3 → 2.0.0 |

历史例子：首次初始化按设备配置选模、九键候选切换等新增能力以 **1.4.0** 发布；之后物理键盘交互批次原定 **1.5.0**，按用户指定调整为 **1.5.1**。如果从 1.3.20 单独交付只含修复的维护包，才会选 1.3.21。这些不是当前待发布版本。大量内部重构不自动意味着 2.0；有兼容迁移且用户原有配置和插件仍可继续使用时，按实际功能影响判断。

规则借鉴 [语义化版本](https://semver.org/lang/zh-CN/) 并应用于输入法的功能和兼容契约；升 MINOR 时归零 PATCH。废止“每次本地修改加末位、正式发包一律加中间位且保留末位”的旧规则。历史发布说明保留原记录，不作为当前规则。

日常编辑、测试和失败重试不改显示版本号。实际交付后不覆盖同号软件内容；后续修复使用新的 PATCH，不再只给 Release 标签加 `-r2` 而让应用显示相同版本。发布前由 Agent 核对远端正式版本、标签及实际源码范围，避免只根据本地旧标签判断。

Android 用独立的 `versionCode` 判断升级顺序，与显示用的 `versionName` 分开；后续交付序号必须增大，见 [Android 版本管理](https://developer.android.com/studio/publish/versioning)。本批初始预留 20261035，从原源码 20261034 递增而来，不是日期；历史覆盖交付的 20261035～20261041 已占用，当前序号见本文顶部。同批普通版与内置版共用版本名和序号；交付前核对所有已有交付记录，若另一对话已使用该序号交付不同源码，则再次递增。不得把每天编辑或同批双版本构建计作两个产品版本，也不得用当天日期覆盖计数器。

## 统一入口

在 `D:/GitHub/CyIME` 使用同一个入口。日常由 Agent 执行，保留命令供用户需要时手动运行；版本从 `app/build.gradle.kts` 读取，不手填、不猜旧包。

```powershell
# 默认：轻量正式包 → 校验 → 保留数据覆盖安装 → 核对设备 APK
.\auto.cmd
# 只检查真实环境，不下载依赖、不构建、不安装
.\auto.cmd --check
# 只构建；设备未连接时，无参数入口也会先完成包
.\auto.cmd --build-only
# 安装当前版本已有校验包，明确不包含尚未构建的修改
.\auto.cmd --install-only
# 明确要求发布时：默认只发轻量包
.\auto.cmd --publish
# 明确要求双包时
.\auto.cmd --publish --both
```

`--full` 选择内置模型版，`--serial SERIAL` 指定多设备中的目标。入口根据仓库本地 `cyime.integrationRoot` 回到集成主目录并打印真实源码位置；不会按版本号猜工作树。相同源码和构建输入复用经过校验的包，设备已有完全相同 APK 时不重复安装。失败返回非零、保留进度，不拿旧包冒充新构建；已记录的同序号不同源码交付会停止，由 Agent 维护下一序号再继续。

脚本不自行提交代码、推送或修改版本。用户要求发布后，这些由 Agent 按功能完成，再调用发布入口；先草稿、上传核对再公开，不覆盖已公开资产。模拟检查及本轮真实入口验证的范围见[工作流审查](development/workflow-review-20261004.md)。

安装前会检查 SuperDisplay 私有 ADB 与 SDK 的协议版本，以及其 1445 转发端口是否被 Windows 保留。发现冲突时先停止交付，避免客户端互相重启；复用 `scripts/repair-adb-conflict.ps1` 修复，端口范围修复需显式加 `-RepairDynamicPorts`。保留 SuperDisplay 的 ADB 连接，具体备份、根因及验证见[共存修复记录](development/adb-superdisplay-coexistence-20261006.md)。

下列脚本是统一入口调用的底层工具，只有需要单独执行某一步时使用：

```powershell
# 正式包（默认）
./scripts/build-apk.ps1
# 调试包，文件名带 -debug，避免误认为正式包
./scripts/build-apk.ps1 -BuildType Debug
```

脚本会把当前构建类型的旧包、另一类型的旧版本包移入
`app/build/outputs/apk/archive/<时间>/<类型>/`，不会删除历史包，也不运行 clean。
构建失败会报错，不会把旧包当成新包。成功后打印实际绝对路径，并生成 `latest.json`（版本、类型、路径、SHA256）。
若构建器将 APK 保存在 `intermediates/apk`，脚本读取其生成的定位文件，限定路径在本次构建目录内，校验应用身份和版本后再复制到交付目录；不猜测或挑选历史安装包。
正式包在 `app/build/outputs/apk/release/`，调试包在 `app/build/outputs/apk/debug/`。
直接执行 Gradle 不会归档旧包，本地发包统一使用上述脚本。

```powershell
# 安装当前 Debug 包（自动识别版本、设备架构和完整文件名）
./scripts/install-debug.ps1
# 正式包安装
./scripts/install-release.ps1
```

安装脚本只选择当前源码版本的对应类型安装包，自动识别设备架构，拒绝旧包或多设备歧义。
有 `app/keystore.properties` 时，Debug 与 Release 沿用同一发布签名与应用 ID。
没有正式密钥的 Debug 是开发构建，不能覆盖正式版；不可通过卸载绕过签名冲突。
`-Action uninstall` 是显式卸载，会删除应用数据，正常更新不要使用。
