# CyIME 0.1.6：语音选择、手写候选和按键效果

版本 `0.1.6`，内部版本号 `20261004`。覆盖安装保持现有应用 ID、签名与用户设置。

## 语音

- 语音模型页固定顺序：Zipformer、Paraformer，两者单选；第三项为 SenseVoice 二次校正开关。切换第一模型保留校正开关，下载与选择分开。
- Zipformer＋SenseVoice 已接入完整双模型链路。两种组合共用分段、逐段校正、有界队列、超时和取消保护；传给独立服务的是完整组合 ID，不依赖跨进程 SharedPreferences 缓存同步。
- Zipformer 收尾仍补右上下文；Paraformer 仍使用流式结束标记。标点转空格，不补句末句号。
- 旧 Paraformer 双模型选择迁移为 Paraformer＋开关开启。原 SenseVoice 单模型设置改为已就绪的 Paraformer 优先，否则 Zipformer，校正开启；若缺少第一模型，页面显示下载，不会偷偷下载或将缺失模型标为就绪。
- 保留每个识别器一个工作线程、有限校正队列和手动开关。8 Gen 2 的顺畅体验来自用户实测；本轮模拟器结果不能代表低端手机热量、耗电、内存或长时间吞吐，不按 CPU 名称自动改选择。

## 日语和光效

- 日语九宫格标点键使用普通按键色，静止时只显示「、」；去掉四周小标点，滑动方向和按住时的选择预览保留。
- 炫光改为 1000 ms，保留主题色相，提高饱和度和可见度。随机圆角方块仍限制在键帽内，文字绘制在其上；连点重启动画，关闭立即清除，默认保持关闭。

## 手写与清理

中文手写候选不再混入非汉字符号，避免低置信度片段把一个字拆成多个；修正原生模型加载失败被误报成功。模型与预处理格式没有替换。固定样例中“一”从“-”恢复，但“中”仍错认，不能宣称汉字准确率已经解决。调查、原始对照、ResNet/CNN 和 ML Kit 方案见 [手写调查](cyime-handwriting-research.md)。

删除没有调用的自写 Zipformer JNI 桥接、七个旧 C++/头文件及其 CMake 目标，删除不再使用的 KNF/kissfft 下载任务和无调用的模型管理接口；安装包只保留正在使用的官方 sherpa-onnx 语音库。ONNX 手写库、Rime 和第三方许可证保留。本轮没有修改中文词库，也不声称全仓已无遗留问题。

## 验证

- JVM 定向 68/68 通过：语音停止/超时/取消、慢二次推理、手写候选、切分与输入会话。
- 新 Zipformer＋SenseVoice 实际音频四段通过：中文、英文、日语、约 55 秒长句。结束收尾约 2～704 ms（模拟器），有错词和个别不理想的日语词内空白；不视为准确率通过。
- 模型设置、两种组合跨进程切换/停止/取消、旧设置迁移、日语手势、炫光时长/裁剪/默认关闭、真实手写模型和失败加载均进行了 Android 验证。
- 最终 Android 回归 23/23 通过（72.391 秒），包括两种组合与两种第一遍单模型的独立服务流程。实际模型、日语键盘与光效截图已检查。assembleDebug 和测试包构建通过；包内旧 asr_jni/kaldi/kissfft 库已确认移除，官方 sherpa-onnx 和手写推理运行通过。最终提交后再校验 GIT_HASH、签名和资源。
- 测试证据在本地 `.gradle/cyime-016/`。首次误装 arm64 包到 x86_64 模拟器被拒，随后使用匹配架构重跑；合成笔画测试最初缺少手写模型，安装并校验原市场权重后重跑。把“丨”误当非汉字的测试样例已更正为 ASCII 竖线；合法汉字部件仍保留。没有操作用户个人手机。
