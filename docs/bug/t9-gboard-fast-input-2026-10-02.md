## 结论

已安装的 T9 修复包确实降低了部分引擎处理耗时，但高速输入的界面绘制仍明显落后于 Gboard。原报告的后台队列耗时不能替代按键到屏幕显示的体验指标。

## 测试条件与口径

- Samsung SM-X800，Android 14，ADB 设备 R52T800SKWZ；横屏 2800 × 1752，覆盖密度 300。
- 两者均为中文九键，使用 CyIME 设置主页的同一个空测试框。没有确认候选或发送测试文字。
- 连续触摸由一个常驻诊断进程通过系统输入接口发送；每键目标间隔 35ms，按下约 10ms 后抬起，不等待候选完成。避免逐次启动 `input tap` 带来的额外延迟。
- 每组两轮；每轮输入 `64426744543` 三次（33 键），等待 1 秒，再连续退格 33 次。两组各 132 次点击。
- 两组实际点击间隔均为：P50 **35ms**，P95 **36ms**，最大发送时间偏差 **2ms**。约每秒 28.6 键，约为此前 145ms/键的 4.1 倍。
- 32MiB 环形 trace 缓冲覆盖了第一轮前段，故不把第一轮作为完整对照。下表统一采用完整保留的第二轮：从首个输入按下到最后一次退格抬起后 500ms，共约 3.786 秒。
- 窗口指标只筛选各自的 `InputMethod` 图层，排除测试 Activity、拼音弹窗和状态栏。CyIME 130 个 frame token 均唯一。trace 未报告非零 `data_loss`；环形缓冲覆盖记录已保留。
- 超时定义为 FrameTimeline 的 `App Deadline Missed`，不是丢字率，也不是将所有 `Buffer Stuffing` 都算成应用超时。保留的预期帧预算为 8.33ms（120Hz）。

## 同一完整轮次的结果

| 指标 | CyIME 九键 | Gboard 九键 |
| --- | ---: | ---: |
| 键盘窗口帧数 | 130 | 317 |
| 应用错过绘制截止时间的帧数 | 102 | 5 |
| 应用绘制超时比例 | **78.46%** | **1.58%** |
| 键盘帧耗时 P50 | 11.333ms | 7.036ms |
| 键盘帧耗时 P95 | **29.616ms** | **14.623ms** |
| 键盘帧耗时最大值 | 55.014ms | 15.113ms |

这里的帧耗时来自实际帧时间线，不是按键到屏幕显示的端到端延迟。总帧数也不能直接当作打字 FPS，两者的动画和空闲重绘策略不同。

同一轮 CyIME 的 33 个数字处理记录中，引擎 flush 耗时 P50 **3.321ms**、P95 **8.367ms**、最大 **8.546ms**。31 次结束于候选绘制提交，2 次 UI 结果被更新的结果替代；后者不等于输入丢失。请求到 trace 结束的 P95 为 48.932ms，但该值不含触摸进入控制器之前的等待，且包含上述两次替代结果，不能称为真实上屏延迟。

此前较慢输入的首轮曾测到约 89ms 的引擎 flush。因此这里只能说重复短句的热路径已较快，不能断言引擎所有情形都没有瓶颈。

## 剩余瓶颈的证据与优先排查点

完整第二轮中，CyIME 主线程出现 264 次 `Recomposer:recompose`、66 次 `AndroidOwner:measureAndLayout`、564 次文本测量及 62 次带尺寸变化的 `relayoutWindow`。`traversal` 单次 P95 为 14.508ms，Gboard 为 2.856ms。

这些主线程计数包含该进程的测试页面与弹窗；切片存在嵌套，不能把它们的耗时简单相加。它们用于定位热点，不作为上表键盘窗口超时率的分母。

下一步按以下顺序修复并验证：

1. 检查 `KeyboardView` 在父层读取整个候选状态造成的重组范围，把候选、左侧拼音选项和按键反馈的更新限制在各自区域。
2. 检查 `CandidateBar.PreeditPreview` 随文字长度改变窗口宽度的路径；保持拼音编辑入口和触控区域，减少每键重新测量与窗口尺寸更新。当前 trace 支持优先排查窗口更新，但尚未通过开关对照证明它是唯一原因。
3. 检查按键效果和可访问性语义更新的触发范围，保留功能，减少无关节点刷新；不能通过删掉可访问性功能来换测试成绩。
4. 将 T9 修复按功能核对后整合到当前源码基线，再按用户指定时机打包。使用同一高速输入脚本检验新包，兼顾首次长句、连续删除及最终候选正确性。

本次对照是用户正在使用的 Debug 修复包与 Gboard 已安装版本。它能证明当前交付体验仍有问题，不能代表 CyIME 经 Release 优化后的性能上限；Android 官方也建议用启用 R8 的 Release 构建评估 Compose 性能：[Compose 性能文档](https://developer.android.com/develop/ui/compose/performance)。
