# 输入交互与状态审查（2026-09-23）

本轮接续手写重做，检查模式切换、面板返回、异步识别、文本修改归属和透明布局，并落实最新的方向键反馈、二次点击返回及手写时长要求。保留此前未提交改动；没有提交或推送 Git，也没有操作用户手机。

## 本轮修复

| 触发场景 | 原问题 | 修正后的行为 |
| --- | --- | --- |
| 编辑面板的方向、选择、复制等操作 | 只执行编辑，绕过按键反馈 | 调用与正常按键相同的声音/震动入口；长按重复也有反馈，尊重现有声音与震动设置 |
| 工具栏再次点击当前编辑、表情、剪贴板等图标 | 重新打开同一面板，不能返回 | 图标保持可见、显示选中状态；再次点击回到进入前的键盘 |
| 50% 透明度打开表情等面板 | 面板从键盘顶部绘制，与工具栏共用同一区域 | 面板从工具栏下方开始；按钮和内容占用不同区域 |
| 手写停笔 | 默认一秒过长，刻度不合要求 | 默认 0.5 秒，0.1～2.5 秒，步长 0.1 秒；再次落笔立即取消等待并重新计时 |
| 手写字后输入空格、标点，再写下一字 | 旧文字仍被当作可替换尾部，导致新字无法追加 | 分隔符结束旧文字的候选归属，新字独立追加；取消候选只撤销当前字 |
| 识别尚未完成时连续点空格、回车、标点 | 后一次功能键取消前一次待执行动作，漏键 | 同一轮笔迹只识别一次，随后按顺序执行全部功能键 |
| 手写期间移动光标、建立选区或切换输入框 | 仅按字数/文本匹配回删，可能误改旧位置；旧识别可能迟到 | 校验输入会话、实际光标位置和预期文字；选区和不同位置文字不被旧候选替换；结束输入立即取消旧会话 |
| 九键→数字→选择英文→再进数字并返回 | 缓存了旧九键页面，界面与英文引擎状态不同步 | 明确切换主模式时清掉旧面板返回状态；返回当前选定模式 |
| 中英文切换失败、异步刷新乱序 | 失败时仍保留乐观状态；较早刷新可覆盖较晚结果 | 失败恢复原模式；只接纳最新方案刷新结果 |
| 语音识别时输入框重启、光标移动到同样的字后面 | 旧结果可跨会话写入，或误修订另一处同样文字 | 语音绑定启动时输入会话；实时修订同时检查文字与位置，退出/重启立即放弃旧会话 |

手写设置位置：**设置 → 布局与显示 → 基础输入 → 手写停顿识别**。旧的一秒默认设置随本轮迁移到半秒；其他旧时长保留并归整到 0.1 秒，新版明确设置的一秒会正常保存。

手写仍使用原市场 ochwpro 模型，语音仍使用原市场 zipformer-zh-int8；没有修改模型文件格式和插件接口。语音部分结果到达后继续实时上屏，点击停止负责收尾。
