# CyIME Windows 剪贴板同步

安卓端 `clipboard_sync` 插件，对接 CyIME-Windows 的 `protocol/clipboard-v1.md`。
目前只同步文本（中文、表情、换行均保留），不包含图片、文件、HTML 或剪贴板历史批量同步。

## 配置

1. 电脑打开 CyIME Windows 的「手机互联」，开启同步和「可信局域网」，允许需要的发送/接收方向。
2. 手机和电脑连接同一可信局域网。在 CyIME「剪贴板同步」中选择内置 Windows 同步服务，无需下载。电脑关闭「加密扫码连接」，开启「允许手机通过局域网连接」并启动同步。
3. 填写电脑显示的地址（例如 `http://192.168.1.50:18740`）和配对码。不要添加 `/api/clipboard`，不用填写用户名。
4. 保存，点击「测试电脑连接」，成功后开启「启用剪贴板同步」。

当前源码已将本插件接入普通版和内置模型版的资源生成与初始化，无需扩展商店。本轮尚未打包、安装；已有旧版 APK 不会因此自动获得内置服务。当前只支持手动连接，不支持 Windows v2 加密扫码。

HTTP 明文协议只用于可信局域网，配对码不提供传输加密。不自动配置防火墙或发现设备；连不上时确认电脑服务已开启、地址可达且网络允许该端口。重置电脑配对码后更新手机配置。

## 行为

- 手机复制文本：在 CyIME 输入法服务存活且系统允许读取剪贴板期间，推送新的系统剪贴板事件；不上传已有历史记录。
- 电脑复制文本：键盘显示期间约每 2 秒拉取一次；收起后停止持续拉取，再次显示时立即检查。不是常驻后台推送服务。
- 首次打开键盘拉取电脑当前内容；协议不提供跨设备时间顺序，不宣称能判断两端哪条历史内容更新。
- 失败推送只保留最新一条，按 5 / 10 / 20 / 30 秒退避重试；关闭同步就取消，不在下次启动补发旧队列。
- 手机在 GET 等待期间又复制新内容时，放弃迟到的电脑内容。写回前再次检查系统内容与时间戳；Android 没有操作系统级原子 compare-and-set，不能宣称消除外部进程在最后读写间隙的所有竞争。
- 只有实际写入手机或内容已经相同，才确认远端 ETag；不能把「请求成功」当成「已经写入」。ETag 只留在运行时，不写入持久配置，换地址/配对码时清空。
- 单条 UTF-8 文本最多 64 KiB；空内容、图片、NUL、校验不符不写入。敏感标记和自动短信验证码不发送。
- HTTP 401、403、409、503 分别提示配对码、方向、冲突、占用问题。运行中的失败交给重试，详细配置问题可通过连接测试检查。

## 实现与验证

- `main.lua` 负责 Basic 认证、GET/PUT、Profile JSON、SHA-256、ETag。
- `ClipboardSyncSession` 负责串行顺序、单条重试、写回检查和回声抑制；`ClipboardSyncBridge` 连接安卓剪贴板与输入法可见状态。
- `foreground_poll_interval_ms` 和 `max_text_bytes` 是插件能力声明；旧 WebDAV 插件不因此变成每两秒轮询，也不套用 Windows 的大小上限。
- LuaJ 3.0.1 的 Java 字符串桥接对补充平面字符使用 CESU-8。本插件通过新增 `host.bin.utf8(text)` 得到真正 UTF-8 字节，用于长度、哈希和请求体，不改变旧的二进制传输行为。
- 本地联调使用真实 Windows `ClipboardServer.cs`、真实 Lua 脚本和 Kotlin 适配器。测试服务仅绑定回环地址、使用内存剪贴板，不读取系统剪贴板；Windows 源码仅按路径引用，不复制进安卓产品。

联调入口见 `tools/clipboard-sync-fixture/README.md`。回环测试不等于 Android 真机、局域网或后台生命周期验收。
